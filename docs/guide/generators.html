Things and layers

An element is a generator, and there are two kinds: a thing makes one solid on its own, and a layer reads the scene so far. A thing can be passed by name.

The result

dharmatiles version="1.0.0"

// A thing passed by name.  `stand` holds a thing in `piece`: a pebble unless the caller says
// otherwise.  It puts one on the ground and scatters three more, so the same recipe draws a
// pebble stand and, called with `piece=boulder`, a boulder stand.
define stand {
    param piece pebble
    stack {
        piece at="(0.3sq, 0.5sq)"
        scatter count=3 { piece }
    }
}

tile size="1x1" seed=12 {
    stack {
        base
        dirt
        stand
        stand piece=boulder
    }
}

Say it plainly

Every element makes something, and it is one of two kinds. A thing is given its controls and a seed and makes one solid, with nothing else to look at: a rock, a stone, a boulder, a pebble, a flower, a tree, and a definition whose stack is exactly one of them. A layer also reads what the stack has built so far: dirt, ground, water and floors paint the ground, and a scatter, a wall or a cliff place their things on it.

Because a thing needs nothing but its controls and a seed, it can be handed around by name. A definition says param leaf pebble, uses leaf like an element, and the caller says which thing with leaf=boulder. A layer cannot be handed around, and the program says so where it is written.

The rules

An element is a thing or a layer

The element schema says which, once, and the element pages say it under Kind. A thing is what a scatter may hold and what at= places on its own; every other element is a layer. A definition is a thing when its stack is one thing, and a layer when it is anything else.

KindTakesElements
thingits controls and a seedrock, stone, boulder, pebble, flower, tree, and a definition of one of them
layerits controls, a seed and the scene so fareverything else: dirt, ground, water, floor, scatter, grass, reeds, wall, cliff

These are two more kinds, checked before anything is built as lengths and angles are (kinds).

A param can hold a thing, and the caller passes it by name

A param holds a thing when its default names one, or when the definition writes it as an entry or as a scatter's child. The caller passes another thing by its name, an element or a definition of one thing, written bare. Inside the definition the param's name calls the thing it holds, so one recipe serves every thing handed to it:

dharmatiles version="1.0.0"

define stand {
    param piece pebble
    stack {
        piece at="(0.3sq, 0.5sq)"
        scatter count=3 { piece }
    }
}

define boulder-ish { stack { boulder } }

tile size="1x1" seed=12 {
    stack {
        base
        dirt
        stand                          // its pebble
        stand piece=boulder            // an element
        stand piece=boulder-ish        // a definition of one thing
    }
}

A param with no default must be given by the caller, as every param must. A thing param is a plain name, and not the name of an element or of a definition (it would call that instead). A definition that holds itself through a param is the same loop as one that calls itself (dt::loop): a thing never makes a thing that makes another.

Properties written where a thing is used apply over its own

The properties written on the entry that calls a thing param, piece size="1dmm .. 2dmm", are the thing's own controls, read as if they were written on the thing itself. The one written there wins; what is not written there is the thing's own default (for a definition, its params' defaults). A property is checked exactly as it is on the thing itself, once the call says which thing it is: its unit and kind (piece size=5 has no unit, as pebble size=5 has none), its range, its words, a control the thing does not take, each refused with the same code and words, at the line where it is written in the definition. A group's controls are written the same way, as lines under the entry (piece { crown width="20dmm" } for a tree).

A param of the definition that fills one of those controls (piece size=s) is typed by it as if the control were written on the thing: the caller's value (stand s=5) and the param's default get the same unit and kind check, range and words, with the same code and words, pointing at the text the caller wrote, however many definitions pass s on. A param fills controls of one kind: piece size=s and piece buried=s (a length and a share) is refused at the param, saying both.

The call that passes the thing passes a name and nothing else: stand piece=boulder cannot reach into the boulder. A thing is tuned where it is used, so two uses of one param in one definition may tune it twice. A thing's own seed is the call path's, like every entry's (seeds): two definitions that take the same thing draw it differently, and an entry written beside another does not move its draw.

dharmatiles version="1.0.0"

define stand {
    param piece pebble
    stack {
        piece size="1dmm .. 2dmm" at="(0.3sq, 0.5sq)"
        piece size="2dmm .. 3dmm" at="(0.6sq, 0.5sq)"
    }
}

tile size="1x1" seed=3 {
    stack {
        base
        dirt
        stand
    }
}

A scatter holds several things by weight

A scatter's children are a list of things, and each one placed picks its child by weight=. A child may be a thing param, and a definition of one thing, as well as an element. This is as far as the language goes: a thing is written once, passed by name or written as a child, or one of several weighted children. It is never a thing that returns a thing.

dharmatiles version="1.0.0"

define pile {
    param bit pebble
    stack {
        scatter count=6 {
            bit weight=5
            rock size="3dmm .. 5dmm" weight=1
        }
    }
}

tile size="1x1" seed=5 {
    stack {
        base
        dirt
        pile bit=stone
    }
}

A layer, a number or a nothing where a thing belongs is refused at the line

The kind is checked where the value is written, with what to write instead (dt::type):

stand piece=dirt      // `dirt` is a layer, and `stand piece` is a thing
stand piece=3         // `stand piece` is a thing, and a number is not
rock size=boulder     // `boulder` is a thing, and `rock size` is a length

A name that is no element and no definition is dt::unknown-element, a thing param left without a value dt::missing-control, and a layer written as a scatter's child dt::scatter naming its kind: dirt is a layer, and a scatter holds things. A param is one kind: one used as a thing and as the value of a control, or as the value of two controls that are not alike (a length and a share), is dt::type too, at the param, saying both.

The editor draws a thing on its own, with a strip of draws and the room it takes: one thing alone.
