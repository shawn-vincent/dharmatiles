Element · the document

tile

Every tile document holds exactly one tile. It says how many squares the tile covers and which seed it grows from, and holds everything else: its heights, lines, regions and stack. The tile has no name of its own: its file name is its name.

Writing it

tile size="1x1" seed=97 {
    about "Water in the lower half, a meadow bank in the upper."
    line shore wobble=5 { through "0,0.38" "1,0.42" }
    region pool { boundedBy shore; fill "0.5,0.25" }
    region bank { boundedBy shore; fill "0.5,0.75" }
    region shoreBand { within 7 of=shore }
    stack {
        base
        dirt {
            pin top="[waterBedHeight .. groundHeight + 1]" at=shoreBand   // anywhere from the bed to the land
            pin top=waterBedHeight at=pool                                // later, so it wins in the pool
        }
        grass at=bank
        scatter at=pool count=2 { rock size="6..10" }
        water
    }
}

Reference

WrittenTakesDefaultWhat it does
size="CxR""1x1"Squares across, then up. A square is 35 mm (DungeonBlocks) or 25.4 mm (OpenLOCK).
seed=a whole number1The root seed. Every element's randomness is keyed from it and the stack, never from the file name, so renaming a tile never changes it; dharmatiles build --seed overrides it.
abouta string—Free text: what the tile is.
leta name and a height—Heights this tile adds; override replaces a library one.
line—Lines, for divided tiles.
region—Areas bounded by lines.
stack—What the tile is made of. Exactly one.

Notes

Above the tile a file may have use lines. Anything else at the top level of a tile document is an error. Positions in the tile are in squares from the south-west corner, x east and y north. The build adds the DungeonBlocks or OpenLOCK base; the document never names it.

The file name is the tile's name everywhere: in the preview, the tile list and the STL (1x1-water+grass.dtile builds 1x1-water+grass-db.stl). To rename a tile, rename its file. Library tiles follow the tile-system naming; your own can be called anything.
