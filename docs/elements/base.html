base

The connector, DungeonBlocks or OpenLOCK: everything below height 0. A stack that has a base starts with it; a stack without one has no base.

On this page
  1. Writing it
  2. Reference
  3. Notes

Writing it

stack {
    base
    dirt
    grass
    water
}

Reference

base takes no settings. Which connector it is, DungeonBlocks or OpenLOCK, is the build target (--system), not the tile, so one tile builds for either.

Notes

The stack is written bottom up and is exactly what is printed. base is the first line, or the tile is refused (dt::base-order); the land follows in stack order, things and grass in any order, and fluids (water) last: anything written after a fluid is refused (dt::fluid-order). A tile that does not use the heights language keeps the order it had. Heights are measured from zero, the base's top, on which the first layer rests.

With no base line the tile has no base: no connector is built, and the tile is printed flat on the bed from zero up, on either system. Its sides run down to zero, its corners keep their round to the bed, and the connector rules do not apply.

The base takes the tile's footprint at zero, with the four vertical corners rounded as the terrain's are (0.5 mm at the 35 mm square, 0.36 mm on OpenLOCK), so the terrain stands flush on it with no ledge: the base's corner polygon lies outside the terrain's by less than 0.02 mm, the lift's error bound. On DungeonBlocks each square's flare turns the tile's corners with it; on OpenLOCK the slab does, and the clip sockets and retention slots (all of which keep clear of the corners) are unchanged.
