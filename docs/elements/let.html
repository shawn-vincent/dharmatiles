let

A named height, length or number. let adds a name to a tile; override replaces one of the library's heights for that tile. Names are camelCase, since a hyphen subtracts, and every name is declared once.

Writing it

tile size="1x1" seed=31 {
    let knollTop  "groundHeight + 4"
    let hump      "groundHeight + [1 .. 2]"   // a range: a little rise, its height left free
    override waterBedHeight 0.8               // deeper water, everywhere on this tile
    stack { base; dirt { pin top=knollTop at=center } }
}

A constant's value is an expression of the constants declared before it: numbers, names, x and y (squares) and bottom (the surface under a body), + - * /, a range in brackets [a .. b] anywhere, and the functions sin cos (degrees), abs, min, max, clamp and smooth. Trigonometry is computed in the program, so a build gives the same bits on every machine.

Notes

One namespace. The library's constants, a tile's lets, its points, lines and regions, and the built-in places are one set of names. Declaring a name that exists, of any kind, is refused (dt::name), and the message offers override when the name is a constant. Only a constant can be replaced; built-in places and element names cannot.

An override holds for the whole tile, library expressions included: overriding waterSurfaceHeight moves waterEdgeHeight with it. An override of a name that does not exist is refused, with a nearby name if there is one, so a misspelt override is caught instead of doing nothing. Overriding an edge height means the tile no longer meets standard tiles without a step. dharmatiles check --explain lists each override (override waterBedHeight 0.4 → 0.8).

Types. Numbers in mm take their meaning where they are used: in a top a height above zero, in within a length; both scale with the system. x and y are squares, so groundHeight + x is refused (dt::type); scale them inside sin or cos, as the tide does. A range is a set: [0 .. 1] - [0 .. 1] is [-1 .. 1].
