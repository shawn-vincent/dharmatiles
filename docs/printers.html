Printers

A printer profile says what your printer is: how big its bed is, where it cannot print, its nozzle, and how many filaments it can hold. Plates are laid out on a profile's bed, and a profile's floors keep every build printable. The library has 49 profiles by brand, you can import your own from the slicers on your computer, and you can write more.

Choosing one

A profile is named by its brand and model, bambu/x1c, or by a plain name, fine. --printer bambu/x1c builds for it (the output goes to out/db-bambu-x1c/: the slash becomes a dash), a print list names one in its plates block, and everywhere a printer is chosen, the title bar’s target card and the plates panel, it is the same chooser: a search, then brand and model, with your own profiles in a group of their own, a profile marked unchecked where its numbers have a verify mark, and an AMS switch under a model that has an AMS profile (x1c and x1c-ams are one model and a switch, not two models). On a print list or a map the title bar’s chip says the printer the document uses (“Bambu Lab X1 Carbon · this print list”), which is the one its plates panel names; the target card then sets the printer tiles are built for. default and fine are the older floors-only profiles: they hold no bed, so they build tiles but cannot hold plates.

A machine profile gives only its machine. The printability floors (line, layer, overhang, steepest, gap) are the default profile's unless the profile writes its own, so the gate judges a tile the same on every printer; --printer bambu/x1c builds byte for byte what the default does.

What a profile holds

WordWrittenMeans
brand, model"Bambu Lab"How the chooser names it.
bed"256x256mm"The printable area: width (x) by depth (y). Plates are laid out inside it.
height"256mm"The tallest print. A tile taller than this is refused.
excluded{ zone "(0mm, 0mm) (30mm, 10mm)" }Parts of the bed nothing may stand on, each two corners, counted from the bed's front-left corner, x to the right and y toward the back, as the printer counts. The packer keeps clear of them and the plates view draws them.
nozzle"0.4mm"The nozzle's diameter (0.4 mm where a profile does not say).
slots4Filaments loaded at once (1 where a profile does not say). A multicolour print list that needs more is refused before anything builds.
template"bambu.3mf"Optional. The slicer project whose printer and process settings a Bambu project takes: a file beside your tiles ($DT_HOME, else ~/dharmatiles); bambu.3mf there is the one used when a profile names none.
verify"sources disagree"Optional. Marks numbers not yet checked against the maker; the chooser and the plates view show it.
from-slicer"Bambu Studio 2.9.1: Bambu Lab X1 Carbon 0.4 nozzle"Optional. Where an imported profile came from: the slicer and its version, then the slicer’s own name for the machine. The chooser marks the profile imported. It changes nothing about the machine and is not inherited by a profile that starts from this one.
from"lib:printers/bambu/x1c"Optional. Start from another profile and change only what is written here.
line, layer, overhang, steepest, gap"0.45mm" …The printability floors (see Printing). A profile with a bed or a from may leave them out.

Lengths carry their unit, mm. A mistake is shown at its text: a bed with no unit, a zone that has no area, a slots that is not a whole number.

dharmatiles version="1.0.0"

printer x1c {
    brand   "Bambu Lab"
    model   "X1 Carbon"
    bed     "256x256mm"
    height  "256mm"
    nozzle  "0.4mm"
    slots   1
}

// x1c-ams.dtile: the same machine with an AMS
printer x1c-ams {
    from    "lib:printers/bambu/x1c"
    model   "X1 Carbon + AMS"
    slots   4
}

Your own

Put a file in printers/ beside your tiles ($DT_HOME, else ~/dharmatiles): printers/shed-voron.dtile is shed-voron, and printers/mine/ender.dtile is mine/ender. A profile of yours with the name of a library one replaces it. It may start from a library one:

dharmatiles version="1.0.0"

printer shed-voron {
    from    "lib:printers/voron/2-4-300"
    bed     "296x296mm"           // what you measured
    slots   1
    excluded {
        zone "(0mm, 0mm) (30mm, 10mm)"
    }
}

Importing from a slicer

If a slicer is installed here, the chooser ends with Import from Bambu Studio… (and one entry for each of the others found). It lists every model the slicer knows, with a search; tick the ones you want and press Import. Each becomes a profile of yours, printers/<brand>/<model>.dtile, marked from-slicer. The command line does the same:

dharmatiles printers import                        # which slicers are installed
dharmatiles printers import bambu --list           # what Bambu Studio has
dharmatiles printers import bambu "x1 carbon"      # a part of the name is enough
dharmatiles printers import orca --all             # every model
dharmatiles printers import cura --path DIR        # a profiles folder of your own choosing

It reads Bambu Studio and OrcaSlicer (machine profiles, JSON with inherits), PrusaSlicer (the vendor .ini files in its settings folder) and UltiMaker Cura (.def.json definitions), each from its app and its own settings folder, read only: nothing is written to a slicer’s folders. Each profile’s inherits chain is followed (PrusaSlicer’s several parents in the order written, the later over the earlier). One profile is made for each model, from its 0.4 mm nozzle profile where there is one. Only what dharmatiles uses is kept:

  • the bed, from the printable area (a round or cut-corner bed is not read and is listed as a profile that could not be used), the height and the nozzle;
  • the zones kept clear (Bambu Studio’s and OrcaSlicer’s bed_exclude_area, as rectangles from the bed’s front-left corner; PrusaSlicer and Cura profiles name none that is read);
  • the filaments: the number of extruders, or a PrusaSlicer MMU’s filaments. A Bambu machine profile does not say whether an AMS is fitted, so a Bambu model also gets an -ams profile beside it (4 filaments a unit, one unit a nozzle); the chooser shows the two as one model with an AMS switch.

A profile already in your folder is kept as it is (--force replaces it). A name the library already uses is never replaced by an import: the imported profile takes -imported after it. Anything that could not be read is listed with the import, never dropped quietly. Check an imported profile against your printer: the numbers are the slicer’s.

Licences

The library’s profiles are written by hand from the makers’ published specifications; none is copied from a slicer. The slicers’ own profile files are other people’s work under their licences: Bambu Studio, OrcaSlicer and PrusaSlicer are released under the GNU Affero General Public License v3, and Cura under the GNU Lesser General Public License v3, with no separate licence for their profile data. That is why importing writes only into your folder, on your computer, for your use, and why nothing a slicer holds is ever added to the library. A bed that is 256 mm is a fact, not a work, but the library still takes its numbers from the maker.
