Tiles in KDL

The three R6 tiles, a new tile written from scratch, and the shared parts, in the vocabulary decided on 1 Nov 2026. Authors write millimetres and named levels, name tile edges instead of walking lines, describe character in words, and list things in any order.

Where this stands. Every example on this page parses as KDL v2 with the kdl 6.7.1 crate and prints back byte for byte. None of them decodes yet: dt-doc and library/*.kdl still use the earlier R6 draft vocabulary. Reworking both to this vocabulary is the next step, in P1 or earlier. The R6 spike results at the bottom were measured on that earlier draft.

How we got here: Shawn read the R6 draft tiles and found them unintuitive. An adversarial review (Could a gamer write these tiles?) read them as a tabletop player would, proposed a modelling vocabulary and rewrote the tiles. Shawn took all ten of its recommendations. This page polishes the review’s rewrites into one consistent set.

The syntax rules as they stand

A tile is a tile node holding an optional about, levels, line and region nodes, and one stack. Each stack entry is a look (dirt, grass, tree, wall, …) or a definition brought in with use, with controls on its line and in group lines below it.

KDL v2

Switches are #true and #false; bare true is a KDL v1 error. Most controls take a word instead (top dirt, coping loose), so switches are rare. /- switches off the next node; """ opens a multi-line string.

Units

None written. Every size is millimetres, measured at the DungeonBlocks reference: a 35 mm square and a 33.1 mm wall top. Positions are in squares, angles in degrees, densities per square, shares in percent. Each control knows its unit.

An optional check is allowed: leaf length=(mm)4.5. A wall-relative height can be written (h)1.2, where h is the 33.1 mm wall top; h is otherwise the engine’s internal vertical scale and authors never need it.

What scales

Write sizes for a 35 mm square; other systems scale them for you. Every size the author writes scales with the system like a photocopy: at OpenLOCK’s 25.4 mm square a 7 mm wall prints 5.08 mm thick and a 4.5 mm leaf 3.27 mm long. Hidden printability floors (blade and leaf thickness, the minimum branch radius, print gaps) never shrink below what prints.

level and height

level is where a surface sits: a named level, mm above the tile base, or an expression such as level="ground - 1". The standard levels are implicit in every tile: edge 3.4, ground 5, water 2.6 and wall-top 33.1 mm. A tile adds its own with levels foot=4.

height is how tall a thing stands above what it stands on, in mm (cliff height=35), or as a word (wall … height full, up to the wall-top level), or as a share of the thing it belongs to (ledges 1 height="40%").

Defaults

The whole tile is the default area, so an undivided tile needs no region. A tile is size="1x1" unless it says otherwise (columns first). ground and dirt sit at the ground level unless given a level. Every look’s defaults are documented; library tiles write out the sizes that matter on the table, such as the tree’s height and the wall’s thickness.

Place words

Four, with one meaning each. in= a region (only needed on divided tiles). along= a line or an edge path. at= a point. against= a kind of thing (cliff, wall, rock, tree): gathers at its foot. With them, seed pins one thing’s look while the tile seed changes the rest. A thing (tree, rock, boulder, oak) is one of itself, placed with at=; how many is never its own control.

scatter

More than one of a thing is a scatter: it says how many and where, and its children say what. scatter per-square=6 mostly=small { boulder size="2..8"; pebble }. count is a total, per-square a density (per square of the area, or of the line’s length along a line); in=, along= and against= say where things may land, and at= with spread makes a cluster. Several children are mixed, in proportion to a weight= on each (default equal). A scatter inside a surface (dirt { scatter … }) lands on that surface. Placement controls live only here, so they are learned once and mean the same for every thing. Decided 1 Nov 2026 (D11).

Edges

The tile edges are north, south, east and west, and a path of edges is quoted: along="north west". A wall or cliff on a tile edge always stands inside the tile, outer face flush with the edge. A drawn line says which side a thing stands on: side=left, right or centre (the default), as you walk the line. A line with a width is a strip, and a look along= it covers the strip.

Points

A point is a quoted pair in squares from the south-west corner, y running north: "0.65,1". Corner words (north-west, south-east, …) and edge words (the middle of that edge) stand in for points.

Ranges and percents

Quoted, because KDL numbers can’t contain .. or %: size="1..6", cover="85%", buried="20%..50%". A range is drawn afresh for each thing. The error for a forgotten quote says what to write.

mostly=

Skews a range draw: size="1..6" mostly=small. small is rockpile’s skew toward the low end (exponent 2), even is uniform, large leans high (exponent ½). It replaces the R6 "1..6^2", which read as 1 to 36.

Words and numbers

Character controls take words that expand to documented numbers: rock mixed is rockpile’s run shares (columns 38, blocks 38, slabs 12, odd 6, monoliths 6), stone-size massive is stones 1.35× rubble size, crown branching=normal is the Python tree defaults. A number is always accepted instead (stone-size "135%"), and the GUI shows the word with the numbers it chose.

Stack order

Free for solids. Every solid thing (rocks, trees, walls, cliffs, scree and boulders) is planned before anything grows, and grass and dirt banks grow round every solid (scattered rocks and trees are solids too) wherever it is listed. Order only decides which surface paints over which: in the path tile, the trodden path dirt is listed after the whole-tile dirt, so it paints over it.

Line or child lines

Both decode the same: cliff along=north height=35, or height 35 as a line inside the cliff’s block. Groups are child lines with properties (leaf length=4.5 width=3). Edits keep whichever form is written. Today edit::set_value only replaces a value that is already there; P1 must add insert, and controls the GUI or an agent adds go on the line as properties.

use

use "parts/grass" lawn long-grass names the file and the definitions it brings in, so a reader knows where every name came from. A definition is called like a look; its params are set as properties (lawn cover="85%"), and place words (in=, at=) pass through to the looks inside it. A definition of a thing can be scattered like any thing: scatter count=2 { oak }.

Expert controls

A few generator knobs stay reachable for parts authors only. The tree’s branch group (split, eagerness, target, balance, exponent, min-radius) is accepted in parts files and refused in tiles, where crown branching= sets it. Debug switches are not tile controls; the review proposes dharmatiles build --show attractors.

2x2-grass-tree

  • No region and no self=: the whole tile is the default area. hills height=ground becomes plain ground, which sits at the ground level unless told otherwise.
  • The tree’s size is on the page, in mm: height=40, trunk height=30, crown width=30. These are the Python defaults (height_mm, trunk_height_mm, and twice canopy_radius_mm), which the R6 draft left invisible. at="1,1" replaces per-square=0.25 (one tree on four squares): a tree is a thing you place. For a spot the seed picks, scatter it: scatter count=1 { tree … }.
  • tips=32 becomes crown clumps=32 (Python’s n_attractors: one foliage clump per branch end). branching=normal is the default, written out because it is the only branching control a tile has. foliage=#true was the default and goes; the switched-off debug node goes too.
  • The grass is listed before the tree, as in Python, and still grows round the trunk: solids are planned first.
  • Correction. The Python tile has GrassCarpet and Tree only, no 3D Grass. An earlier version of this page said the twin’s grass replaced “the carpet and the 3D blades”. It replaces the carpet alone, and because the grass look grows standing blades (grasslab v3), the twin adds standing grass the Python tile never had. That is a look change for P4 to confirm.
  • Blade curl was a fraction of π (0.35–0.65); it is now 63–117°. The 0.2 mm blade clearance is a print gap and is hidden.
Python it replaces: 2x2-grass-tree.tile.py 
"""2x2 grass meadow with one Tree (space-colonisation growth, Bezier tubes)."""

from dharmatiles.spec import Tile, Region, FloodFill, SurfaceConfig, SpeciesConfig, D
from dharmatiles.layers import GrassCarpet
from dharmatiles.scatter import Tree, Grouped, Uniform

_species = SpeciesConfig(
    blade_length=D[8:14],
    blade_curl=D[0.35:0.65],
    blade_clearance=0.2,
)

tile = Tile(
    surface=SurfaceConfig(cols=2, rows=2, seed=84),
    areas=[
        Region(
            id='meadow',
            selector=FloodFill(0.5, 0.5),
            layers=[
                GrassCarpet(
                    species=_species,
                    placement=Grouped(groups_per_square=3),
                ),
                Tree(
                    placement=Uniform(count_per_square=0.25),
                    debug_attractors=False,
                    foliage_clusters=True,
                    n_attractors=32,
                    leaf_length_mm=4.5,
                    leaf_width_mm=3.0,
                ),
            ],
        ),
    ],
)

1x1-wall-fieldstone-corner

  • along="north west" replaces a six-number line and the left-of-the-walk rule. On a tile edge the wall stands inside, outer face flush, which is the DungeonBlocks slab standard Python follows.
  • height full and thickness 7 replace top wall (h) and thickness 0.2 (squares). On OpenLOCK the wall still prints 5.08 mm thick, and now its stones shrink with it, so the stones-per-thickness ratio no longer changes between systems.
  • Five masonry words become three groups a modeller can picture: stones height length (were course, bay), joints width depth (joint, reveal) and edges rounding (roundover). coping perched / vertical becomes loose / on-edge, and family becomes style.
  • The meadow region with its leftover Python fill point (0.5, 0.35) goes. The wall’s seed=14 pins its stones while the tile seed varies everything else.
  • Unchanged from R6: SoilCarpet becomes dirt (dirtlab), and Python’s two grass layers, carpet before the wall and blades after it, become one lawn.

# 1x1-wall-fieldstone-corner.tile.py
#
# Drystone fieldstone wall turning the NW corner of a grassy 1x1.
# Wall body extends to the LEFT of the spine walk (into the tile);
# outer face flush to the tile edge — the DungeonBlocks slab standard.

    SpeciesConfig

from dharmatiles.scatter import Grass

    areas=[
        Region(id='meadow', selector=FloodFill(0.5, 0.35), layers=[
            SoilCarpet(),
            GrassCarpet(species=_species),
            FieldstoneWall(spine=[(1.0, 1.0), (0.0, 1.0), (0.0, 0.0)], seed=14),

2x1-cliff-run

  • levels foot=4 and height=35 replace heights foot=0.121 and height 1.057. The cliff’s height is above its foot, the dirt it stands on. The 4 mm override stays until rockpile moves to the 3.4 mm edge level in the lab, before P7 (question 6).
  • along=north replaces the drawn line back, and one edge implies the run form, so form=run goes. Two edges make a corner; P7 must generalise rockpile’s band forms to drawn lines (a canyon) or restrict along to edges.
  • mass 1.35 becomes stone-size massive; the five-way stones column= block= … share becomes rock mixed; dirt-on-tops #true becomes top dirt; shatter zones= becomes shattered patches=3: patches on this cliff (1.5 per square over its two squares), a feature of the cliff rather than things scattered.
  • The bank says what it leans on: near=cliff becomes against=cliff. The dirt is listed before the cliff and still banks against it, which is now the general rule rather than a special case.
  • Rockpile’s grit becomes pebbles scattered on the dirt, where it lies, with sink renamed buried. Scree is no longer a look of its own: it is stones and boulders scattered against=cliff, and a rock scattered against a cliff takes its fragment shapes from the cliff’s rock, so the scree kinds mix goes. "1..6^2" becomes size="1..6" mostly=small.

A new tile, from scratch

The tile the R6 examples could not produce: a 1×2 grass strip with a winding dirt path and a cluster of rocks. It is the first example of a divided tile, so it is the first to need a region.

  • The path is a line with a width and a wobble (Shawn’s boundary with a width, and his controllable organic randomness). Its ends are edge words, the middles of the south and north edges.
  • The verge region is the tile less the path: bounded-by trail and a fill point on each side. Both lawn and rocks are kept in=verge; the scatter clusters five rocks within about 6 mm of its at= point.
  • The second dirt paints over the first along the path, 1 mm lower: here order matters, because both are surfaces.
  • New to dt-doc: width and wobble on lines, bounded-by (R6 wrote lines), scatter with at and spread, and the level expression. All are in the design conversation or the plan; none is a new concept.

Two more next tiles

ledges is exposed in P7, from rockpile’s tier height (TIER_Z) and full-height share (FULL_P); the tiers already exist inside the run form. A ramp (escarpment’s 10–40 mm along the run) stays inside the escarpment form until a second look needs one (question 7).

Shared parts

The parts files hold definitions that tiles bring in by name. lawn is Python’s default grass species and long-grass calls it with longer, curlier blades, a definition built on a definition. The standard levels move from h to millimetres, and a trees file shows where the expert branch controls live.

parts/grass

  • The look inside is grass (was meadow), so it no longer shares a name with regions called meadow. clumps becomes tufts, the hobby word, and a cover share is added.
  • clearance is hidden, as a printability floor. long-grass had set it to 0.2 mm; that value now belongs to the look.

The standard levels

wall is renamed wall-top, so it reads as a level, not a thing. The file is still a prelude every tile sees without a use line (question 8).

parts/trees

The oak’s numbers are illustrative, not tuned. A tile places one as oak at="1,1" height=60, or several as scatter count=2 { oak }.

Vocabulary, per look

Each look leads with a handful of author controls named for what you see, taken from the review’s tables. Sizes are mm at the reference scale, positions are squares, angles degrees, densities per square. A word in a choice expands to the generator’s numbers; a number is always accepted too. The hidden knobs stay inside the look.

Decisions

Later the same day, after reading the draft tiles and the adversarial review, he took all ten of the review’s recommendations. Editing one control

The GUI and agents will change a value through the kdl crate’s document API. Three edits, one per file, printed by cargo run -p dt-doc --example roundtrip:

library/parts/grass.kdl: define long-grass > stack > lawn > Prop("length")

 29 -         lawn length="8..14" curl="63..117" clearance=0.2
 29 +         lawn length="9..15" curl="63..117" clearance=0.2
    the other 30 lines are byte-identical

library/tiles/ground/2x2-grass-tree.kdl: tile grass-tree > stack > tree > leaf > Prop("length")

 18 -             leaf length=4.5 width=3.0           // mm
 18 +             leaf length=5.5 width=3.0           // mm
    the other 24 lines are byte-identical

library/tiles/cliffs/2x1-cliff-run.kdl: tile cliff-run > stack > cliff > height > Arg(0)

 27 -             height 1.057            // 35 mm above the foot: the run form's cap
 27 +             height 1.2            // 35 mm above the foot: the run form's cap
    the other 46 lines are byte-identical

The tests check more than the line diff: the bytes before and after the changed value are identical, every library file prints back unchanged after a parse, the slashdashed node and the multi-line about survive, and two successive edits compose. One limit: when the new value is shorter or longer, a comment later on that line moves with it. Nothing re-aligns comment columns. A second limit: edit::set_value only replaces a value that is already written, in whichever form it is written; adding a control the file does not mention is P1 work.

The dt-doc crate

  • Parse with kdl 6.7.1, then decode by hand: one function per node type (tile, define, param, line, region, stack entry, group), with one control table per look in schema.rs. No derive crate.
  • Every name and value keeps its byte span. Errors are miette diagnostics with a code, a label at the span and a help line. Decoding continues past the first error, so a file’s mistakes come together.
  • Values go through a small expression parser: arithmetic on parameters and named heights, ranges "a..b" with an optional skew ^k (a draw is a + (b − a)·u^k, rockpile’s rule), percents. No calls, loops or assignments.
  • Dependencies: kdl and miette only (no default features). It builds for wasm32-unknown-unknown, which CI now checks.
  • Two things learned about KDL v2: two nodes on one line need a ; after a closing brace, and the crate’s own messages are generic (“Expected identifier string”), so dt-doc rewrites the common ones (v1 keywords, unquoted ranges).
