Revision 4: project plan

  1. Shawn accepted the revision 3 recommendations ("i like the recommendations. can we put together a phased project plan for the rust rewrite?"). A new project plan page turns them into nine phases (P0–P8), each with a goal, scope by crate and Python module, measurable exit gates, risks retired, dependencies, size and Shawn's own tasks.
  2. The migration order is refined in four places: the walking skeleton and parity harness come before dirt; walls, floors, OpenLOCK and trees run as a parallel stream; the library cutover comes before the cliff (no library tile uses one); front ends arrive across the phases instead of last.
  3. Open questions get the recommended default, marked "assumed" on the plan page (15 of them), so nothing blocks on them.
  4. Shawn's new rule: HTML is preferred, Claude documents are never hand-edited, and all artifacts live under docs/. CHANGELOG.md and the eleven notes-*.md files were converted (to this page and a new research notes page) and deleted.

Revision 3: project layout

A layout pass on the Rust repository, checked against crate and tool status on 1 Nov 2026 (sources and dates in the research notes) and against the language conversation for the GUI, mobile, MCP and plugin rulings. 12 entries, L1–L12.

  1. A new project layout page places every part of the Rust version: one Cargo workspace at the repo root beside the untouched Python, the tile library as KDL in library/ embedded in the program, output in out/, user files in standard per-platform folders.
  2. Fifteen crates became six (dt-geom, dt-kit, dt-doc, dt-looks, dt-eval, dharmatiles). The language crate split so the document model builds without geometry.
  3. CLI and MCP are one program with subcommands; the GUI is a Tauri app whose web front end is also the browser preview.
  4. The feasibility page now says plainly what reaches the browser and phones: everything but the C++ Manifold, which needs the pure-Rust port for a browser build.

Revision 2: the most important changes

  1. Documents no longer call engine verbs. Writing each lab's approved look as a composition of the seven verbs needed 7 to 11 extra constructs per lab, so the architecture now has two layers: declarative documents that name built-in looks with natural controls, and a Rust engine kit of about twenty shared operations.
  2. The verb set was wrong in four places. relieve merged two mechanisms (face relief and grain); pack merged the cliff's gravity stack with wall courses, which have no gravity; stroke blades are a layer stack, not a sweep; seat has several bed rules. These are now partition, relief, grain, loft (layer-stack mode) and a seat with named bed rules.
  3. A plan-then-build evaluation rule replaces the single bottom-to-top pass, because rocks in a meadow must claim footprints before the grass and be seated after it.
  4. Several of Shawn's rulings had been overridden without saying so, and are restored: fractions for every length, regions only from lines and fill points (no self - bare), water over the whole tile (no connected:), one definition form, unlimited nesting, and named standard heights.
  5. Water semantics, the 'union once at export' claim, rocklab's seat, the core's 'never daylight', and about thirty smaller facts were corrected against the code. A new feasibility page covers crates, determinism, hosting (KDL), live preview, testing, migration order and ten risks with spikes.

D2designmechanisms.html, engine set; architecture.html, kit table
Before
relieve: one verb that displaces a surface by a field in a world, face or normal frame. It covers soil texture, clods, grain, wave relief and crack grooves.
Now
Split into relief (depth raster of a solid in a face frame → clamp → lift → subtract), grain (refine, then displace along normals with masks), and field operations for heightfield texture.
Why
Face relief ray-casts the stone, clamps, lifts and subtracts (rockpile.py:1255–1332). Grain is subdivision plus vertex displacement (rocklab.py:283). Dirt relief is grid arithmetic before lift (dirtlab.py:507).
D3designmechanisms.html; architecture.html; notes-synthesis.md
Before
pack: gravity-fill a target with solids. It is scatter + seat in a loop, and the cliff stack, wall courses and fieldstone fill are all this solver.
Now
partition, with three methods: gravity (cliff), courses (wall bond) and tessellate (fieldstone cracks first). Its output is units, not solids.
Why
Wall _layout is a deterministic split with no gravity or scene reads (walls/masonry.py:286–365). Fieldstone is partition then loft (walls/fieldstone.py:668–735). The cliff stack picks the lowest cell, grows footprints and merges crumbs into earlier stones (rockpile.py:554–782).
D4designmechanisms.html; architecture.html
Before
build: carve, sweep or lift. Stroke blades are a sweep with a stroke_stack profile.
Now
carve (hull or prism ∩ half-spaces, with guards, rounding and booleans), loft (along a curve or graph, a morphing profile, or a layer stack with drape), and lift (adaptive heightfield to solid).
Why
Each blade layer is its own 2D stroke over a different span of the spine, lofted through 2D SDFs and sheared onto the hills (grasslab.py:812–911). Tree tubes need C1 forks across a graph (trees/mesh.py:938–1030).
D5designmechanisms.html, seat
Before
seat: a bed quantile or plane, plus a plinth. Covers rocks, scree, wall bases and cliff stones.
Now
seat with a named bed rule: quantile, plane fit, cones at the overhang limit, or minimum ground; plus sink, plinth and clearance.
Why
Cliff undersides are a max of cones at 38° from the bed plus a bevel (rockpile.py:1530–1564). Scree uses minimum ground minus sink (rockpile.py:1800). rocklab uses a fixed sink (rocklab.py:396).
D6designmechanisms.html, fill; architecture.html, shore example

Now
One fill: per column, raise the top to a surface (a level, or a level plus a field) where the ground is below it, with a margin; bury elsewhere. Closing is a field operation; a film is relief.
Why
No water lab uses connectivity: waterlab floods unconfined (waterlab.py:1050) and shorelab uses a 0.6 mm margin on the wet mask (shorelab.py:245). Shawn wanted water over the whole tile (L2293, L2345).

Regions included self - bare, where(field > t), scatter-grown region.bare, band(line, width), and a bank: { along: shore } that targets a line.
Now
Regions are paint buckets only. Derived lines (offset, contour) feed the same bucket, and a band is two offset lines plus a fill point. Soft areas are fields passed as parameters.

Before

Before
Connectors live in dt-print and attach at export. OpenLOCK becomes a connector parameter instead of a full rerun.

D19designarchitecture.html, representation cards
Before
No universal representation. Lenses over tagged solids. Lazy fields, eager geometry.
Now
The mesh is the common format, with native fast paths (a lifted heightfield answers top() directly). Plan lazily, build eagerly, and cache by path, seed and inputs.
Why
Solid = mesh made the mesh universal, which contradicted 'no universal representation'. Shawn left lazy vs lenses open (L3786), and ChatGPT left object list vs implicit volume open (L3899).

Before
