The tile language · guide

The tile language

A tile is a short .dtile text file that names built-in elements (ground, dirt, grass, rock, tree, wall, cliff) and says where they go. You write millimetres for a 35 mm square, name tile edges instead of walking lines, describe character in words, and list things in any order. The files are KDL v2 underneath. This page is the guide; every element has its own page in the elements reference.

1. What a tile document is

A tile document is one .dtile file holding exactly one tile node. The tile has a size and a seed, and a body with (its file name is its name: tile takes none):

  • about: optional free text, one string;
  • let and override: optional named heights this tile adds or replaces;
  • line and region: only for tiles divided into areas;
  • stack: exactly one, listing the elements and definitions that make the tile.

Above the tile, a file may have use lines that bring in definitions from parts files. Parts files hold define nodes. Two library files use two more top-level nodes: printer (the printer profile) and edges (the edge contract). Anything else at the top level is an error.

The smallest tile in the library:

// library/tiles/test/1x1-flat.dtile
tile size="1x1" {
    about "Flat ground at the edge height (3.4 mm) on one square: the first tile built end to end."
    stack {
        base
        dirt top=dirtEdgeHeight clods=none   // flat, at the edge height (3.4 mm)
    }
}

Its stack starts with base, the connector; a stack with no base line has no base, and prints flat on the bed from zero. dharmatiles build lib:tiles/test/1x1-flat.dtile builds it for DungeonBlocks, the default system.

element
Anything a document can write: the document's own (tile, line, region, stack, …) and the built-in terrain (dirt, grass, rock, tree, wall, cliff, …), plus scatter. Each has a page in the elements reference.
control
A setting of an element, written as a property (height=40) or as a child line (height 40).
group
A control that holds only sub-controls, written as properties on its own line: leaf length=4.5 width=3.
thing
One solid object: a rock, a tree, or a definition whose stack is one thing (an oak).
definition
A named, reusable stack (define lawn { … }) that a tile calls like an element.

2. Syntax basics

Documents are KDL v2, a small, readable configuration language, checked by the program against the tile language, so every error message is written for you, at the line it is about.

RuleExampleNotes
A node is a name, then values and properties, then an optional block.tree size=40 { … }Properties are key=value; a block is { … }.
A control may go on the line or as a child line.cliff height=35 or cliff { height 35 }Both decode the same. Edits keep whichever form is written; new controls go on the line.
Ranges, percents and points are quoted.size="1..6", cover="85%", at="0.65,1"KDL numbers can't contain .., % or ,. A forgotten quote gets an error that says what to write.
Switches are #true and #false.—Bare true is KDL v1 and an error. Few controls are switches: most take a word (clods some, leaves bare).
// comments a line; /- switches off the next node./- tree
""" opens a multi-line string.about """ … """
Several nodes on one line are separated by ;.region verge { boundedBy trail; fill "0.15,1" }

Values inside quotes

A quoted value is a tiny expression:

value  := sum ( ".." sum )?        a range "lo..hi", drawn afresh per thing
sum    := prod ( ("+" | "-") prod )*
prod   := unary ( ("*" | "/") unary )*
unary  := "-" unary | atom
atom   := number "%"? | name | "(" sum ")" | "[" sum ".." sum "]" | weighting      see Weighted ranges

A range is written lo..hi or [lo .. hi], in a control value as in a height, and the brackets go anywhere a number does: size="[1 .. 2] + [3 .. 4]" adds two ranges. A bare lo..hi reaches over sums, so 1..2 + 3 is 1..5; but when a value holds two bare ranges, or one beside a bracket or a weighting, each .. binds tighter than the arithmetic and 1..2 + 3..4 is two ranges added. The brackets always say it plainly.

A name is a parameter of the enclosing definition or, where a height is expected, a let name: level="groundHeight - 1", level="wallHeight / 2". The only calls in a quoted control value are the weightings below; there are no loops or assignments. % is the only suffix.

Weighted ranges

A range that is drawn once per thing can say which parts of it are likelier. The range goes inside a function:

weighting := ("flat" | "low" | "high" | "bell" | "peak" | "ends") "(" range ( "," number )* ")"
           | "steps" "(" range ( "," weight )+ ")"
           | "mix" "(" part "," weight ( "," part "," weight )+ ")"       part := a call above, over the same range
list      := "[" item ( "," item )+ "]"                                   item := value ( ":" weight )?
range     := sum ".." sum | "[" sum ".." sum "]"

Nine functions in all. A comma inside brackets makes a list; .. makes a range.

scatter at="foot(cliff)" perSquare=55 reach=4 { stone size="low(1..6, 11)" }
scatter perSquare=3 { rock size="bell(6..10)" }
scatter perSquare=3 { stone size="[3, 4:3, 5.5]" }
let small "low(1..6, 11)"

Each curve is the density over the range: higher means likelier, the dotted line is the plain range. A list has no density, so its values stand as bars, as tall as their share.

The numbers. low and high take a ratio over 0 (4 by default, no upper limit). bell and peak take a spread of 0.05 to 1 and a centre of 0 to 1. ends takes a power of 0 to 8 (1 by default) and the valley's centre. steps takes 2 to 32 weights and mix 2 to 16 parts; a list holds up to 64 values. A weight is 0 or more, and at least one must be above 0. A number outside its limits is dt::range, with the limits in the help; dharmatiles elements rock lists every function with its defaults and limits.

Lists. [1:4, 2:5, 3:1] draws 1, 2 or 3, each as likely as its weight; a missing weight is 1, so [1, 2, 3, 4, 5, 6] is a six-sided die, and on a count (count, stems) the same as 1..6. On a size, 1..6 is every size between and the list is only the sizes written: size="[2, 5:3, 8.5]". A weight of 0 is allowed beside one above 0. A value written twice is a dt::weighting error, and its help gives the list to write: [1:4, 2:6] for [1:4, 2:5, 2:1]. Values are drawn in ascending order, so a list moves and scales like any range.

Mix. mix(bell(1..6), 3, flat(1..6), 1) is three parts bell to one part flat. Every part is written over the same range (a different one is a dt::weighting error), and a part is a call, never a list or another mix.

Written alone, a range is flat on every element. a..b and [a .. b] both read inside a call, in a quoted control value and in a height. The numbers after the range are plain numbers; a strength outside its limits is dt::range, with the limits in the help.

  • Every range is its own draw. Write a range twice and it rolls twice: [1 .. 2] + [3 .. 4] is two dice. Each range draws from its value's own key and its position in the value, so editing one value never moves another's draws.
  • A weighted range goes on a draw, not on a band. A top=, a pin's top and a within distance are bands the solver fits, not draws: low(…) there is a dt::weighting error whose help gives the range to write. flat(…) is the plain range and is accepted anywhere a range is.
  • A let name holds a distribution. let small "low(1..6, 11)" stands for that range with its odds, and a control that names small draws from it, each use its own roll. A tile's own let may be named by a size, count or density control; the library's heights may not.
  • A count has an equal chance for every whole number. A range on a count (count, perSquare as the number it makes, reeds' clumps and stems) is cut into one bin per whole number, ends rounded: 2..5 gives 2, 3, 4 and 5 a quarter each, the ends no rarer than the middle. A weighting moves the odds across the bins; a sum falls in the bin of its drawn place along its ends.
  • Sums are dice. size="[1 .. 2] + [3 .. 4]" (or "1..2 + 3..4") adds two rolls and lands anywhere in 4..6, most often near 5. A name holds the range, not a roll, so s - s with let s "[1 .. 2]" is two rolls, anywhere in -1..1. Numbers and names shift and scale, and a negative factor mirrors. Dividing by a range is refused. On a count the sum is rounded, and a band (top=, a pin) reads a sum as the interval it spans.
  • A weighting wraps a plain range: low(bell(1..6)) and low(3) are dt::weighting errors. An unknown function is dt::value. A weighting on a range of no width has no effect, and check says so in a note.
  • Every control that draws takes a weighting. A size, a count, a density, a course or a bay of a wall, a blade's length or height, how deep a rock is buried, how wide a shattered patch is, a tree's heights and a point's range in at=. A control that is a band never does. The "takes" column of each element page says weighted range where it applies.

What every stack entry takes

  • seed=: pins this entry's own randomness while the tile seed changes everything else.
  • id=: a name for the entry, for edits and diagnostics.
  • weight=: only on a child of a scatter, its share of the mix.
  • The place words its element accepts (section 5).

3. Units, heights and scaling

The rule for an author is one sentence: write sizes in millimetres for a 35 mm square; other systems scale them for you.

No unit is ever written. Each control knows what it measures:

Kind of valueWritten asOn another system
Sizemm at the DungeonBlocks reference: thickness 7Scales like a photocopy
Levela named level, mm above the tile base, or an expression: level=foot, level="ground - 1"Scales like a photocopy
Positionsquares from the south-west corner: at="0.65,1"Follows the square
Densityper square: perSquare=45Follows the square
Angledegrees: branch split=34Unchanged
Sharepercent, quoted: cover="85%"Unchanged
Count, word, switchcount=5, rock mixed, #trueUnchanged

Two optional annotations exist. (mm)4.5 is only a check. (h)1.2 writes a height in wall tops (h is the 33.1 mm official wall top); you never need it. "4.5mm" is an error.

What scales

Every size the author writes scales with the system. At OpenLOCK's 25.4 mm square a 7 mm wall prints 5.08 mm thick and a 4.5 mm leaf 3.27 mm long. The hidden printability floors never shrink: they come from the printer profile, library/printers/default.dtile:

printer default {
    line     0.45       // one extruded line, mm: the thinnest wall that prints
    layer    0.2        // one layer, mm
    overhang 55         // what every element aims for, degrees from vertical
    steepest 65         // small patches up to here
    gap      0.2        // the narrowest gap that stays open, mm
}

Other profiles sit beside it in library/printers/ (fine), and your own in a printers/ folder beside your tiles; --printer chooses one. A profile holds the printer's floors only: the base system is chosen with --system, and edge and corner rounding belong to materials.

Elements apply these after scaling, so a scaled blade, leaf or branch is never thinner than what prints.

level and height

level is where a surface sits. height is how tall a thing stands above what it stands on: mm (cliff height=35), a word (wall … height full, up to wallHeight), or a share of the thing it belongs to (ledges 1 height="40%").

Named heights are let constants. The library's come from library/parts/heights.dtile and every file sees them without a use line: dirtEdgeHeight 3.4 mm, groundHeight 5, waterSurfaceHeight 2.6, wallHeight 33.1 and the rest of that file.

A tile adds its own with let foot 4 and replaces a library one with override. A level or a line's wobble may name any of them (those that depend on x or y excepted). Heights scale with the system like every other size. See let.

Heights: let, override, tops and pins

Heights are written in one way everywhere: millimetres above zero, the top of the base. A number (top=8), a named height, or an expression of them. Named heights are let constants in camelCase, since a hyphen would read as subtraction; the library's are in library/parts/heights.dtile and every tile sees them:

let waterBedHeight     0.4     // the bottom of standing water: two print layers
let waterSurfaceHeight 2.6     // calm water
let waterEdgeHeight    "waterSurfaceHeight + 0.6 * cos(720 * (x + y))"   // the tide at a tile edge
let dirtEdgeHeight     3.4     // where dirt meets a tile edge
let groundHeight       5       // open land
let floorHeight        7.4     // a built floor's top
let floorEdgeHeight    floorHeight
let shortWallHeight    16.55
let wallHeight         33.1
let tallWallHeight     72.3

A tile adds its own names with let and replaces a library one with override (override waterBedHeight 0.8 deepens the water's bed everywhere on the tile, and moves every library height that reads it). Every name is declared once, of any kind: a let on a name that exists, or an override of one that does not, is refused (dt::name), and the message gives the other keyword or the nearest name. See let.

A height may use numbers, names, x and y (squares), bottom (the surface under this body, or under the thing), + - * /, a range in brackets anywhere (groundHeight + [1 .. 2]), and the functions sin and cos (degrees), abs, min, max, clamp and smooth. Measures are checked: groundHeight + x adds squares to millimetres and is refused (dt::type).

A body of the stack (dirt, water, cliff, flagstones, planks) says how high it may be with its top=, a band: a single height fixes the surface, a range leaves it room. A pin holds the band to a height at a place; where pins overlap the later one wins, and the library's defaults (below) are read first. The stack is written bottom up: base first, the land in order, things and grass where you want them, water where you want it: after the ground it fills over, and before whatever should stand in it or on its shore. The stack is built in the order it is written.

stack {
    base
    dirt top="[groundHeight .. groundHeight + 2.5]" {
        slope 30                                  // how steeply this dirt lies; 24 by default
        pin top=knollTop at=knoll
    }
    water at=banks                                // fills over the ground listed above it
    grass at=meadow                               // listed after the water: keeps off the wet ground
}

Defaults. library/parts/edges.dtile also holds the tops and pins every body starts with, read before the tile's own lines:

defaults {
    dirt  top="[groundHeight .. groundHeight + 1]" { pin top=dirtEdgeHeight at=edges }
    flagstones top=floorHeight                     { pin top=floorEdgeHeight at=edges }
    planks top=floorHeight                         { pin top=floorEdgeHeight at=edges }
    water top="[waterSurfaceHeight - 1.9 .. waterSurfaceHeight + 3]" { pin top=waterEdgeHeight at=edges }
}

A tile's own top= replaces the default top, and its pins win over the default pin wherever they overlap. The dirt default applies to the first dirt only, so a second dirt laid over what is under it (dirt top="bottom + [0.6 .. 1.2]") is not pulled to the rim; the water, flagstones and planks defaults apply to every water and every floor. dharmatiles check --explain lists every default applied and where it came from, each override (override waterBedHeight 0.4 → 0.8), and each pin's share of its place.

What check does with them. Besides reading the names and types, check solves each body's band on a lattice (no meshes, tens of milliseconds): the pins hold the band exactly where they are, dirt eases back toward the others no steeper than its slope (water settles over 9 mm; cliffs and floors do not ease: their stones and slabs step), and the result is the band the body fills. It refuses what cannot be solved and notes what looks wrong (the codes are in Errors). build solves the same bands again on the build's own lattice and fills them: a dirt draws hills in its band, a water draws its waves inside it, and a floor draws each slab's or board's height and tilt inside it. A cliff draws its stones inside its band, as a floor draws its slabs. A thing's top= is checked but not built yet, and says so.

A complete tile that builds:

tile size="1x1" seed=62 {
    point crossing "(0.65, 0.5)"
    line stream wobble=0.5 { through westCenter eastCenter }
    region banks { within 11.5 of=stream }
    region bed   { within 1.5 of=stream }
    stack {
        base
        dirt {
            pin top="[waterBedHeight .. groundHeight + 1]" at=banks       // anywhere from the bed to the land
            pin top="[waterBedHeight .. waterBedHeight + 0.3]" at=bed     // later, so it wins inside the bed
        }
        water top="[waterSurfaceHeight - 1.9 .. waterSurfaceHeight + 3]" at=banks
        rock size="6..10" at=crossing
        grass
    }
}

The edge contract

Every tile also reads library/parts/edges.dtile, without a use line. Its defaults block gives the first dirt, and every water, a top and a pin at the tile's edges, so that neighbours butt with no step:

defaults {
    dirt  top="[groundHeight .. groundHeight + 1]" { pin top=dirtEdgeHeight at=edges }
    water top="[waterSurfaceHeight - 1.9 .. waterSurfaceHeight + 3]" { pin top=waterEdgeHeight at=edges }
}

So any dirt tile butts any other with no step, and any two water tiles meet in the same wave. A pin the tile writes later wins over a default where they overlap. See edges.

4. Edges, points, lines and regions

Positions are in squares from the south-west corner, x running east and y running north.

ThingWritten asMeans
Tile sizesize="2x1"Columns first. Default "1x1".
Edgenorth, south, east, westFor a thing, a point: the middle of that edge. For a wall, surface or scatter, a line: that edge.
Edge pathat="north west"Several edges in order, quoted. Two edges meeting make a corner.
Cornernorth-west, south-east, …A point at that corner.
Point"0.65,1"One quoted pair. Either coordinate may be a range, weighted or not: "0.6..1.4,0.6..1.4" or "bell(0.6..1.4), 0.5", drawn once from the tile seed.

A wall or cliff on a tile edge always stands inside the tile, its outer face flush with the edge. That is the DungeonBlocks slab standard, and it means an author never has to work out which side of a line a wall is on.

Lines

A drawn line runs through points. With a width it is a strip, and a dirt, grass or cliff at= it fills the strip (within half the width, wobble included), and a scatter reaches half the width either side unless it writes reach. A surface along a line with no width, or along a tile edge, is dt::type. wobble lets it wander up to that many mm off its points.

line trail width=9 wobble=3 { through south "0.65,1" north }

An element along a drawn line takes side=left, right or centre (the default), as you walk the line. side= along a tile edge is an error, because on an edge a wall always stands inside.

Regions

The whole tile is the default area, so an undivided tile needs no region. A region exists only when lines divide the tile. It is the paint-bucket model from the design conversation: name the lines that bound it, then drop one or more fill points.

region verge { boundedBy trail; fill "0.15,1"; fill "0.85,1" }

Several fill points on different sides of a line join areas without union, intersection or difference. Elements act inside a region with at=verge.

Places by name

A place is a point, a line or a region, all flat: they say where, never how high. Every tile has them built in, named in camelCase:

KindDeclaredBuilt in on every tile
pointpoint knoll "(0.28, 0.72)"northWestCorner northCenter northEastCorner westCenter center eastCenter southWestCorner southCenter southEastCorner
lineline stream wobble=4 { through … }, closed=#true for a loopnorthEdge eastEdge southEdge westEdge, and edges for all four
regionregion meadow { … }tile, the whole tile (which is also what no at= means)

A place is written as a name or as a literal point "(x, y)" in squares from the south-west corner; today's "x,y" still reads. A region is its fill points and its discs less what it excepts:

region banks { within 4.5 of=stream }                     // a disc round a point, a strip beside a line, a ring round a region
region verge { except path }                              // a region that only excepts is the whole tile less those
region knoll { boundedBy foot; fill center }             // the paint bucket, as before

One place word, at=, says where an entry goes, and it takes any place: a point, a line or a region. Each element takes the kinds that mean something to it and refuses the others with dt::type and a help line: a body, grass or reeds fills a region (a body or grass may also follow a line); a wall follows a line; a thing stands at a point or fills a region, and given a line it is refused (a line has no one place on it: write a scatter); a scatter fills a region or spreads along a line, within reach mm either side of it, and given a point it is refused (write a region round it, within 5 of=knoll). With no at= an entry covers the whole tile. within, except and boundedBy build places; they never use one. See point, line and region.

5. Placement and scatter

Place words

One word, at=, names the place, and side= adjusts a line. Each element page lists the kinds of place it takes.

WordTakesMeans
at= a regiona region nameActs only inside that region. Default: the whole tile.
at= a linea line, an edge or an edge pathBuilt or spread along it. On a tile edge, always inside.
at= a pointa point, ranges allowed, or a corner or edge wordCentred there, or drawn once within the range. No at=: anywhere in the area.
at="foot(cliff)"foot( cliff, wall, rock or tree ), quotedThe band at the foot of that kind of thing, where a scatter gathers. reach= says how far out.
side=left, right or centreAlong a drawn line, which side the element stands, as you walk the line. Not on a tile edge.

A wall must have at= a line; a cliff needs it for the edge forms (run, corner, escarpment) but not the free-standing ones. Surfaces take a region and usually a line; things take a point or a region. An entry has one place: a second at= is dt::duplicate, and the old in=, along= and against= are dt::unknown-control naming at= (dharmatiles migrate rewrites old tiles).

One thing

Things share one vocabulary. A rock (and stone, boulder, pebble), a tree and a flower are placed the same way, with at= a point or a region they stand in, and sized the same way, by size=, which takes a number, a range or any weighting (size="low(1..6, 11)"); a tree's size is its height and a flower's the width across its petals. Many of them are a scatter whose children are things: scatter at=meadow perSquare=4 { flower size="4..6" }. A scatter holds rocks, flowers and trees, alone or mixed: each placed item picks its child by weight=, and one gap keeps every two things apart (trees are placed first, then rocks, then flowers); trees keep their crowns clear of one another, and scatter at=road count=3 { tree } is a row of trees along a line. A thing is one of itself. How many is never its own control: tree count=3 is an error whose help says to use a scatter. With no at= a thing goes anywhere in its area. Either way its footprint is kept inside the tile and clear of other solids, nudged inward rather than clipped (D12).

scatter

More than one of a thing is a scatter. It says how many and where; its children say what.

ControlTakesWhat you get
countnumber, or a weighted rangeHow many, in total.
perSquarenumber, or a weighted rangeHow many per square of the area, or per square of length along a line.
reachmmWith at="foot(…)": how far out from the foot.
clumpsper squareGathers them into clumps. Default: spread evenly.
gapmmLeast space between neighbours.
child weight=numberShare of the mix when there are several children. Default: equal.

A scatter must have exactly one of count and perSquare; reach needs at="foot(…)". A scatter inside a surface (dirt { scatter … }) lands on that surface.

Stack order

The stack is built in the order it is listed. Each entry stands on the terrain as laid so far, and what is listed after it is laid over or beside it. Land bodies are laid in stack order, each the higher of what is below and its own top: a dirt along a path, listed after the whole-tile dirt, takes the higher of the two there. A dirt listed after a rock, a tree, a flower or a scatter of them is built after them: it lies on the tops of rocks where they are flatter than its maxSlope, banks up to a trunk or a stone (a rise is no drop), and covers a flower's foot, as written. A tree's crown is never a surface for dirt. A dirt listed before them is laid first, and they stand on it (a rock beds into it). Grass grows round what is listed before it, so list the grass after the rocks, trees and flowers it should grow round; the same goes for water, which fills over the ground listed above it and sees the rocks and reeds listed above it (each sends its own chop). What is listed after the water stands in it or on its shore and reads it: a rock stands in the pool, and grass keeps off the wet ground. A dirt or ground listed after the water lies over it: where its top is higher than the water the earth shows, where it is lower the water stays. Water is built where it is listed, like every other layer; nothing is written about it last.

The plan refuses what the listed order cannot satisfy, with dt::order and the entry's place, and never reorders to cure it: a tree, grass or wall listed above the first ground or dirt it stands on, a thing that reads another kind (grass that needs rocks) with the first of that kind listed below it, a floor listed above a surface it lies on. Two things are placed by what they are, not by where they are written: the lift (the one solid the surfaces make together) comes right after the last surface, water or floor, and base, which reads the finished tile, is built last.

7. Parts: use, define, param

Parts files hold definitions that tiles bring in by name. A use line names the file and the definitions it brings in, so a reader knows where every name came from:

use "parts/grass" lawn long-grass

A bare path such as "parts/grass" is the bundled library, and "lib:parts/grass" says so explicitly. "./mine" or "../shared/x" is a file in the author's project. Anything else is an error.

A define has param lines and one stack. It is called like an element; its params are set as properties, and a place (at=) passes through to the elements inside it. A definition can call another. A definition whose stack is one thing is itself a thing, so it can be placed with at= or scattered: scatter count=2 { oak }. Definitions that call each other in a loop are an error (dt::loop).

// library/parts/grass.dtile
define lawn {
    param length "3.5..6.5"   // blade length along the ground, mm
    param height "1.5..2"     // how tall a blade stands over the ground, mm
    param clearings 0         // patches of bare earth per square
    param cover "100%"        // share of the ground grassed over

    stack {
        grass length=length height=height clearings=clearings cover=cover
    }
}

// Long, tall blades: the species of 2x2-grass-tree.
define long-grass {
    stack {
        lawn length="5..9" height="2..3"
    }
}

A param's default is typed by the control it fills, so param length 10 is checked as a size in mm. A param without a default must be given by the caller. A tile has no params. Expert controls live in parts files:

// library/parts/trees.dtile
define oak {
    param height 50           // ground to the top of the crown, mm

    stack {
        tree size=height {
            trunk height=18
            crown width=44 clumps=60 shape=wide
            branch split=34 eagerness=0.6 target=0.25 balance=0.8 exponent=3 minRadius=0.9
        }
    }
}

A tile places one oak as oak at="1,1" height=60, or several as scatter count=2 { oak }.

8. Errors

Every mistake gets a message with a stable code (such as dt::unknown-control), the line it is on with the spot underlined, and a hint that says what to write instead. The program reads on past a mistake, so all of a file's mistakes come together. dharmatiles check my-tile.dtile reports them without building; the preview shows them beside the tile. Some examples:

dt::syntax

  × `1..6` must be quoted

Other mistakes caught the same way: a misspelt control (clumsp, did you mean clumps?), a unit written in ("4.5mm"), an expert control in a tile, a wall without at=, side= on a tile edge, and old KDL v1 syntax.

Refusals of the heights language

Three phases, each as early as it can know. The static ones are found reading the document; the solve ones when check works out the bands. Every refusal gives the place, the values and what would fit.

CodePhaseWhen, and an example
dt::namestaticA name declared twice, a let on a name that exists, an override of one that does not, a built-in place or element name reused, a name that is not camelCase.
`groundHeight` is already declared — help: override groundHeight … replaces it for this tile
dt::typestaticMeasures that do not agree, or a place of the wrong kind.
`dirt` fills a region, and `northEdge` is a line; `top`: a sum mixes a plain number and squares (x or y)
dt::unknown-name, dt::placestaticA height or a place that nothing declares, with the nearest name.
no place is called `southCentre` — help: did you mean `southCenter`?
dt::pinstaticA pin without top= or at=, or a pin on something that is not a body.
a pin needs at=
dt::base-orderstaticbase anywhere but first, or a second one.
the base is the first line of the stack
dt::weightingstaticA weighted range on a band (top, a pin, within), a weighting that does not wrap a plain range, or a control that takes none yet.
a weighted range does not go on a band — help: write the range alone
dt::emptysolveA pin whose place covers nothing.
this pin's place `nowhere` covers nothing
dt::thinsolveA layer that can never be as thick as the printer's skin (three layers).
the dirt is at most 0.30 mm thick at (17.50, 17.50) mm, under the 0.60 mm the printer's skin needs
dt::missing-controlsolveA body with no top and no default, such as a cliff.
dt::steepnotePins force dirt past its slope.
the dirt is forced to 43.8°, steeper than its 24° slope: 5.33 mm up to 5.59 mm over 0.27 mm
dt::shadowednoteA pin of the tile’s own that wins nowhere because later pins cover all of its place. A pin the library supplies is never reported: covering it is how a tile overrides it.
dt::edgenoteWhere the tile's own pins move a body off the library's edge height, so it no longer butts a standard tile.
the dirt meets the tile's edge at a height of its own … along the south edge 0.00 to 1.00 (squares)

A note does not stop the build; check prints it after the tile's line. The pins named in a note are the ones that cause it.

9. Worked examples

Whole tiles, each with what it shows. Every one builds as written: copy it into a .dtile file and run dharmatiles preview on it.

A grass meadow with one tree

// library/tiles/ground/2x2-grass-tree.dtile
// A 2×2 grass meadow with one tree.

use "parts/grass" long-grass

tile size="2x2" seed=84 {
    stack {
        base
        dirt clods=none
        tree size=40 {               // anywhere on the tile; or at="1,1"
            trunk height=30             // bare trunk below the crown
            crown width=30 clumps=32 shape=round branching=normal
            leaf length=4.5 width=3
        }
        long-grass                      // listed after the tree, so it grows round the trunk
    }
}
  • No region: the whole tile is the default area.
  • The tree has no at=, so it goes anywhere on the tile. at="0.6..1.4,0.6..1.4" would keep it near the middle.
  • The grass is listed after the tree, so it grows round the trunk; listed before it, the tree would stand in the grass.
  • long-grass grows standing blades.

A fieldstone wall turning a corner

// library/tiles/walls/1x1-wall-fieldstone-corner.dtile
use "parts/grass" lawn

tile size="1x1" seed=64 {
    stack {
        base
        dirt                                // bare earth at the ground height

        // Along the north edge, then the west edge.  On a tile edge a
        // wall always stands inside, its outer face flush with the edge.
        wall at="north west" style=fieldstone seed=14 {
            height full                     // up to wallHeight (33.1 mm)
            thickness 7
            coping loose                    // or: on-edge

            // fieldstone's own defaults, written out to show them
            stones height="2.2..5.2" length="5..16"
            joints width=0 depth=2.8        // how deep the gaps between stones look
            edges rounding="1.3..2.6"       // worn corners
        }

        lawn
    }
}
  • Two edges in at= make a corner.
  • The wall's seed=14 pins its stones while the tile seed varies everything else.
  • On OpenLOCK, the 7 mm thickness and the stone sizes all shrink with the square.

A cliff run

// library/tiles/cliffs/2x1-cliff.dtile

tile size="2x1" seed=1 {
    about """
        Rock band against the north edge. Both ends finish in the
        standard end section, so runs butt end to end.
        """

    region crag  { within "[10 .. 20]" of=northEdge }
    region apron { within 6.5 of=crag }

    stack {
        base
        dirt top=dirtEdgeHeight {
            pin top="[dirtEdgeHeight .. dirtEdgeHeight + 3.5]" at=apron   // the bank, drawn
            pin top="dirtEdgeHeight + [1.5 .. 3.5]" at=crag
            scatter perSquare=45 { pebble size="1..2.2" buried="20%..50%" }
        }

        cliff top="dirtEdgeHeight + 35" at=crag {
            rock mixed                  // or: columns, blocks, slabs
            stoneSize massive          // or: rubble, broken
            shattered patches=3 width="5..10"
        }
        dirt top="bottom + [0.6 .. 1.2]" at=crag   // dirt on the cliff's top

        // scree: fallen stones gathered at the cliff's foot
        scatter at="foot(cliff)" perSquare=55 reach=4 { stone size="low(1..6, 11)" }
        scatter at="foot(cliff)" perSquare=2.5 { boulder size="4.5..8" }
    }
}
  • let foot 4 adds a height for this tile.
  • The dirt is listed before the cliff and still banks at="foot(cliff)". Its pebbles are scattered on the dirt.
  • Scree is stones and boulders scattered against the cliff; they take their fragment shapes from the cliff's rock.

A divided tile: grass, a path and rocks

A path of bare dirt winding up a 1×2 tile through grass, with rocks beside it: lines, regions and at= together. (It is a test document in the repository, crates/dt-doc/tests/fixtures/1x2-grass-path-rocks.dtile.)

use "parts/grass" lawn

tile size="1x2" seed=7 {

    // From the middle of the south edge to the middle of the north edge,
    // 9 mm wide, wandering up to 3 mm off its points.
    line trail width=9 wobble=3 { through south "0.65,1" north }

    // Everything beside the path: one fill point on each side of it.
    region verge { boundedBy trail; fill "0.15,1"; fill "0.85,1" }

    stack {
        dirt                                    // the whole tile, at the ground height
        dirt at=trail                        // the path, a second dirt along it

        scatter at=verge count=5 {
            rock size="4..10" shape=rounded buried="30%"   // shape: or angular, flat
        }

        lawn at=verge cover="85%"
    }
}
  • The second dirt is laid after the first along the path; each land body is the higher of what is below it and its own top.
  • verge is the tile less the path: one fill point on each side of the line.

Rules of the language

  • A tile is a declarative document, not a program: KDL v2 underneath, saved as a .dtile file.
  • Sizes are millimetres at the 35 mm DungeonBlocks square; heights are millimetres or let names. Units are not written: 4.5, never "4.5mm" ((mm)4.5 is an optional check).
  • Every size a tile writes scales with the system, like a photocopy; hidden printability floors keep it printable. Print-scale detail (grain, blades, leaves) keeps its printed size.
  • Ranges and percents are quoted: size="6..10", cover="35%".
  • A plain range is flat, on every element. A weighting is written round it, size="low(6..10, 3)"; every range in a value is its own draw; a weighted range goes on a draw, not on a band; a let name holds a distribution.
  • Points are quoted pairs in squares ("(0.5, 1)"), a point's name, or a corner or edge word.
  • The whole tile is the default area. A region is flat: its fill points and its within discs, less what it excepts. One word, at=, names any place (a point, a line or a region), and each element refuses the kinds it cannot use with dt::type: a body or grass fills a region or follows a line, a scatter fills a region or spreads along a line (never a point), a thing stands at a point or fills a region. foot(cliff) is the band at that kind's foot.
  • A stack that uses the heights language is written bottom up: base first, the land in order, water after the ground it fills over. Heights are mm above zero; a pin is exact where it is and the later pin wins; the library's defaults are read before the tile.
  • Every name is declared once, in camelCase, and so is every control: perSquare=55, not per-square=55. A hyphenated control name is an unknown-control error that gives the new one, and dharmatiles migrate rewrites old tiles. let adds a name, override replaces a library one, and neither works on the other's names.
  • Stack order is build order: every entry is built in the order it is listed, standing on the terrain laid so far, and the plan refuses (dt::order) what that order cannot satisfy rather than reorder it. Land bodies are laid in stack order, each the higher of what is below it and its own top.
  • Character controls are words that stand for documented numbers; a number is always accepted too.
  • A wall or cliff on a tile edge stands inside the tile.
  • scatter places many things; a thing on its own is one, placed with at=. An at= may be a range, drawn once from the tile seed; with none, a thing goes anywhere in its area, kept inside the tile and never clipped.
  • Water fills its area up to its top; the shoreline comes from the dirt beneath.
  • The library's heights (groundHeight, dirtEdgeHeight, waterSurfaceHeight, wallHeight and the rest) are always there.
  • z = 0 is the top of the base; the base owns everything below it.
  • Materials are named in the document and given colours separately, by a palette.
  • Controls sit on the element's line as properties, or as child lines.
