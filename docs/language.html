The tile language · guide

The tile language

A tile is a short .dtile text file that names built-in elements (ground, dirt, grass, rock, tree, wall, cliff) and says where they go. Every length carries its unit (8dmm), points are written across and down from the tile's north-west corner ("(0.65sq, 1sq)"), heights read the library's $ names, and character is described in words. Things are built in the order they are listed. The files are KDL v2 underneath. This page is the guide; every element has its own page in the elements reference.

1. What a tile document is

A tile document is one .dtile file holding exactly one tile node, after a header line. The tile has a size and a seed, and a body with (its file name is its name: tile takes none):

  • about: optional free text, one string;
  • let and override: optional names this tile adds or replaces (section 3);
  • point, line and region: places, for tiles divided into areas;
  • stack: exactly one, listing the elements and definitions that make the tile.

Between the header and the tile, a file may have use lines that bring in definitions from parts files. Parts files hold define nodes. Two library files use two more top-level nodes: printer (the printer profile) and defaults (the edge contract). Anything else at the top level is an error.

The header line and the format

A document of any kind (a tile, a parts file, a printer profile, a palette) starts with one line that says which version of the language it is written in:

dharmatiles version="1.0.0"

It is the first node of the file, once; it takes version= and nothing else. By hand the major number is enough: dharmatiles version=1. A version with a second dot or a + is quoted, since KDL reads a bare 1.10 as the number 1.1. Only the major part matters to reading: it is the document's format, and this program reads format 1. The editor writes the full version of the program that wrote the file, as the library's files do ("1.0.0"); re-saving a document leaves the line as it is.

A document with no header is format 0, the language before this one, and this program does not read it: the decoder refuses it with dt::format-0, wherever the tile is shown (the CLI, the preview, the editor); its help names release 1.0.0 (tag v1.0.0), which carries a file to format 1 with dharmatiles migrate. A document of a newer format than the program reads is refused with dt::format-newer. A header out of place, repeated or malformed has its own error (dt::header, dt::header-first, dt::header-twice, dt::header-version).

dharmatiles --version and the editor's About box (in the view's ⋯ menu) give the program's own version and the formats it reads. The program's version is drawn from git: X.Y.Z at the release tag vX.Y.Z; X.Y.Z+N.gHASH on main, N commits past it; X.Y.Z+branch.N.gHASH on another branch; and .dirty added when the engine's files have uncommitted changes. A build record carries it.

The smallest tile in the library:

dharmatiles version="1.0.0"

// library/tests/ground/1x1-flat.dtile
tile size="1x1" {
    about "Flat ground at the edge height (3.4 mm) on one square: the first tile built end to end."
    stack {
        base
        dirt top="$dirtEdgeHeight" clods=none   // flat, at the edge height (3.4 mm)
    }
}

Its stack starts with base, the connector; a stack with no base line has no base, and prints flat on the bed from zero. dharmatiles build lib:tests/ground/1x1-flat.dtile builds it for DungeonBlocks, the default system.

element
Anything a document can write: the document's own (tile, line, region, stack, …) and the built-in terrain (dirt, grass, rock, tree, wall, cliff, …), plus scatter. Each has a page in the elements reference.
control
A setting of an element, written as a property (height="40dmm") or as a child line (height "40dmm").
group
A control that holds only sub-controls, written as properties on its own line: leaf length="4.5dmm" width="3dmm".
thing
One solid object: a rock, a tree, or a definition whose stack is one thing (an oak).
definition
A named, reusable stack (define lawn { … }) that a tile calls like an element.
tile, square, cell
The whole printed output; one 35 mm DungeonBlocks unit (25.4 mm for OpenLOCK) of it; one subdivision of a square that the program works in. sq is the unit for a square.

2. Syntax basics

Documents are KDL v2, a small, readable configuration language, checked by the program against the tile language, so every error message is written for you, at the line it is about.

RuleExampleNotes
A node is a name, then values and properties, then an optional block.rock size="8dmm" shape=flat { … }Properties are key=value; a block is { … }.
A control may go on the line or as a child line.cliff height="35dmm" or cliff { height "35dmm" }Both decode the same. Edits keep whichever form is written; new controls go on the line.
Anything with a unit, a range, a $, a percent or a point is quoted.size="1dmm .. 6dmm", cover="85%", at="(0.65sq, 1sq)", top="$groundHeight"KDL numbers can't contain letters, .., %, $ or ,. A forgotten quote gets an error that says what to write. A bare number is for counts, densities and fractions (count=3, perSquare=45).
Switches are #true and #false.—Bare true is KDL v1 and an error. Few controls are switches: most take a word (clods some, leaves bare).
// comments a line; /- switches off the next node./- tree
""" opens a multi-line string.about """ … """
Several nodes on one line are separated by ;.region verge { boundedBy trail; fill "(0.15sq, 0sq)" }

Values inside quotes

A quoted value is a tiny expression:

value  := sum ( ".." sum )?        a range "lo .. hi", drawn afresh per thing
sum    := prod ( ("+" | "-") prod )*
prod   := unary ( ("*" | "/") unary )*
unary  := "-" unary | atom
atom   := number unit? | number "%" | name | "$" name | call | "(" sum ")" | "[" sum ".." sum "]" | weighting      see Weighted ranges

A range is written lo .. hi or [lo .. hi] in a control value, and the brackets go anywhere a number does: size="[1dmm .. 2dmm] + [3dmm .. 4dmm]" adds two ranges. In a height (a top=, a let) and inside a call, a range is always in brackets. A bare lo .. hi in a control value reaches over sums, so 1dmm .. 2dmm + 3dmm is 1dmm .. 5dmm; but when a value holds two bare ranges, or one beside a bracket or a weighting, each .. binds tighter than the arithmetic. The brackets always say it plainly.

A name is a parameter of the enclosing definition or a let of the tile (a plain name), or a name starting with $ that the context supplies (section 3). The calls are the weightings below, the functions sin cos abs min max clamp smooth, the coordinates x y d a and parent, and point and polar (section 6); there are no loops or assignments. A number may be followed by a unit (8dmm, 90deg), and by % (section 4).

Weighted ranges

A range that is drawn once per thing can say which parts of it are likelier. The range goes inside a function:

weighting := ("flat" | "low" | "high" | "bell" | "peak" | "ends") "(" range ( "," number )* ")"
           | "steps" "(" range ( "," weight )+ ")"
           | "mix" "(" part "," weight ( "," part "," weight )+ ")"       part := a call above, over the same range
list      := "[" item ( "," item )+ "]"                                   item := value ( ":" weight )?
range     := sum ".." sum | "[" sum ".." sum "]"

Nine functions in all. A comma inside brackets makes a list; .. makes a range. The range carries its units like any other value (section 4): 1dmm .. 6dmm for a size, 0.2sq .. 0.6sq for a position. The numbers after the range are plain numbers and have none.

scatter at="foot(cliff)" perSquare=55 reach="4dmm" { stone size="low(1dmm .. 6dmm, 11)" }
scatter perSquare=3 { rock size="bell(6dmm .. 10dmm)" }
scatter perSquare=3 { stone size="[3dmm, 4dmm:3, 5.5dmm]" }

Each curve is the density over the range: higher means likelier, the dotted line is the plain range. A list has no density, so its values stand as bars, as tall as their share.

The numbers. Only the range has units; the numbers after it are plain. low and high take a ratio over 0 (4 by default, no upper limit). bell and peak take a spread of 0.05 to 1 and a centre of 0 to 1. ends takes a power of 0 to 8 (1 by default) and the valley's centre. steps takes 2 to 32 weights and mix 2 to 16 parts; a list holds up to 64 values. A weight is 0 or more, and at least one must be above 0. A number outside its limits is dt::range, with the limits in the help; dharmatiles elements rock lists every function with its defaults and limits.

Lists. [1:4, 2:5, 3:1] on a count draws 1, 2 or 3, each as likely as its weight; a missing weight is 1, so [1, 2, 3, 4, 5, 6] is a six-sided die, and on a count (count, stems) the same as 1..6. On a size, 1dmm .. 6dmm is every size between and the list is only the sizes written: size="[2dmm, 5dmm:3, 8.5dmm]". A weight of 0 is allowed beside one above 0. A value written twice is a dt::weighting error, and its help gives the list to write: [1:4, 2:6] for [1:4, 2:5, 2:1]. Values are drawn in ascending order, so a list moves and scales like any range.

Mix. mix(bell(1dmm .. 6dmm), 3, flat(1dmm .. 6dmm), 1) is three parts bell to one part flat. Every part is written over the same range (a different one is a dt::weighting error), and a part is a call, never a list or another mix.

Written alone, a range is flat on every element. a .. b and [a .. b] both read in a quoted control value; inside a call, or in a height, the brackets are the way to write it. The numbers after the range are plain numbers; a strength outside its limits is dt::range, with the limits in the help.

  • Every range is its own roll, everywhere. Write a range twice and it rolls twice: [1dmm .. 2dmm] + [3dmm .. 4dmm] is two dice, in a control, in a top=, in a pin and in a tree's crown alike; there is one evaluation of a value, and a range is one roll wherever it stands. Each range draws from its value's own key and its position in the value, so editing one value never moves another's draws.
  • A weighted range on a top is a cloud. A body's top= and a pin's top may be a weighted range (section 5, Clouds). A within distance is read as a band, not a draw: low(…) there is a dt::weighting error whose help gives the range to write. flat(…) is the plain range and is accepted anywhere a range is.
  • A let name holds a distribution. let small "low(1dmm .. 6dmm, 11)" stands for that range with its odds, and a control that names small draws from it, each use its own roll. A tile's own let may be named by a size, count or density control; the library's $ heights may not.
  • A count has an equal chance for every whole number. A range on a count (count, perSquare as the number it makes, reeds' clumps and stems) is cut into one bin per whole number, ends rounded: 2..5 gives 2, 3, 4 and 5 a quarter each, the ends no rarer than the middle. A weighting moves the odds across the bins; a sum falls in the bin of its drawn place along its ends.
  • Sums are dice. size="[1dmm .. 2dmm] + [3dmm .. 4dmm]" adds two rolls and lands anywhere in 4dmm to 6dmm, most often near 5dmm. A name holds the range, not a roll, so s - s with let s "[1dmm .. 2dmm]" is two rolls, anywhere in -1dmm to 1dmm. Numbers and names shift and scale, and a negative factor mirrors. Dividing by a range is refused. On a count the sum is rounded. A band (top=, a pin) spans the interval of the sum (top="[1dmm .. 2dmm] - [1dmm .. 2dmm]" is a band from -1dmm to 1dmm) and its heights come up as two dice do, most often near 0.
  • A weighting wraps a plain range: low(bell(1dmm .. 6dmm)) and low(3) are dt::weighting errors. An unknown function is dt::value. A weighting on a range of no width has no effect, and check says so in a note.
  • Every control that draws takes a weighting. A size, a count, a density, a course or a bay of a wall, a blade's length or height, how deep a rock is buried, how wide a shattered patch is, a tree's heights and a point's range in at=. A control that is a band never does. The "takes" column of each element page says weighted range where it applies.

What every stack entry takes

  • seed=: pins this entry's own randomness while the tile seed changes everything else.
  • id=: a name for the entry, for edits and diagnostics.
  • weight=: only on a child of a scatter, its share of the mix.
  • The place words its element accepts (section 5).

3. Names: $ names, let and override

A name is one of two kinds, and the $ says which.

KindWrittenWhere its value comes from
$ names$x, $d, $bottom, $region, $groundHeightThe context: a record of $ names that every formula is called with. The library installs its heights in it, an element sets the position names at each point it works out, and a let $name adds one of your own. Whatever calls a formula or a definition passes its context on, changed only where it says so.
plain namesknollTop, a definition's lengthThe place they were written: a tile's own let, a definition's param. They are never passed to a definition you call.

The two are separate namespaces: a parameter called length never hides anything with a $, and $high is a fine name though high is a weighting.

WrittenDoesError when
let $treeLine "40dmm"puts a new $ name in the context, for everything in this blockthe context already has it: use override (dt::name)
override $groundHeight "6dmm"replaces a $ name for this block and everything called from it; when the block ends the old value is backno caller installed it (the message offers the nearest name), or an element sets it itself ($x $y $d $a $bottom $region $tile)
let knollTop "$groundHeight + 4dmm"declares a plain name, oncethe name is already declared, or is a word of the language

let and override work at the top of a tile and inside any block (scatter { override $treeLine "40dmm"; tree … }), and take effect for the rest of that block, the entry they sit in included. A let holds a formula, read where it is used: let $floorEdgeHeight "$floorHeight" follows an override $floorHeight made below it. A $ name read where no caller installed it is dt::unknown-name at that spot, and check works out which names each part reads at each place it is called, so a part that reads a name its caller does not have is refused at that call. Plain names are camelCase, since a hyphen would read as subtraction (dt::name).

dharmatiles version="1.0.0"

tile size="1x1" seed=31 {
    let knollTop "$groundHeight + 4dmm"        // a plain name: this tile's own
    let $treeLine "40dmm"                      // a $ name: the context, read by whatever is called below
    override $waterBedHeight "0.8dmm"          // deeper water, everywhere on this tile
    stack {
        base
        dirt { pin top="knollTop" at=center }
        scatter count=3 {
            override $treeLine "30dmm"         // for this block only
            tree top="$bottom + $treeLine"
        }
    }
}

The names the library installs

The library's heights come from library/parts/heights.dtile and every file sees them without a use line, as $ names in design millimetres above zero (the top of the base):

let $waterBedHeight     "0.4dmm"            // the bottom of standing water: two print layers
let $waterSurfaceHeight "2.6dmm"            // calm water
let $waterEdgeHeight    "$waterSurfaceHeight + 0.6dmm * cos(720deg * ($x - $y))"   // water at a tile edge: two waves a square
let $dirtEdgeHeight     "3.4dmm"            // where dirt meets a tile edge
let $groundHeight       "5dmm"              // open land
let $floorHeight        "7.4dmm"            // a built floor's top
let $floorEdgeHeight    "$floorHeight"      // where a built floor meets a tile edge: flush
let $shortWallHeight    "16.55dmm"          // half the wall top
let $wallHeight         "33.1dmm"           // the standard wall top
let $tallWallHeight     "72.3dmm"

Beside them an element sets the names a formula may read at each point it works out:

NameIsKind
$x, $ywhere the point is in the tile, in squares from its north-west corner: x($tile, sq) and y($tile, sq)plain number
$dhow far in from the edge of the thing's own region: 0 wherever deepest in the interior, 1 right at the edgeplain fraction
$ahow far round the region: 0 at east, turning towards the south as the page reads (a quarter is straight down), 1 a full turnplain fraction
$bottomwhat the thing stands on at that point: the surface below it in the stack (the base for a first dirt, the dirt under a second, the ground at a tree's foot, a water's bed)length
$regionthe region of the thing being built (section 6)region
$tilethe whole tile, the root regionregion

A body (dirt, water, flagstones, planks, cliff) sets all of these at each point of its region. A tree sets all of these at each branch tip, with $region its own disc round the trunk and $bottom the ground at its foot; every other element sets $region. check knows this before any build: reading a name the element does not set is dt::unknown-name at the exact spot, with what the element does set. Because $x and $y are the tile's, neighbouring tiles' heights meet, like the water's shared tide. Local position in a region is one call away: x($region, sq).

Reserved words

A plain name (a let, a param) may not be a word of the language; it is a dt::name error that names the word and its kind.

coordinatesx y d a parent
functionssin cos abs min max clamp smooth point polar
weightingsflat low high bell peak ends steps mix
unitssq mm in layer deg rad pi dmm

let a 3 is refused, with help to choose another name. Node names (line, layer in a printer file) are not plain names, so they keep theirs.

4. Units and kinds

The rule for an author is one sentence: write every length with its unit; dmm is the design millimetre, 1/35 of a square, and scales with the system.

Nothing is guessed. A length is a number and a unit; an angle is a number and deg or rad; everything else (a count, a density, a share, a fraction) is a plain number.

UnitMeasuresIsScales with the system?
sqlengthone square: 35 mm on DungeonBlocks, 25.4 mm on OpenLOCKyes: it is the grid
dmmlengtha design millimetre: exactly 1/35 of a square, so 1 mm on DungeonBlocks and about 0.73 mm on OpenLOCKyes, with the grid
mm, inlengtha printed millimetre, a printed inch: what calipers and the slicer measureno
layerlengthone printed layer: 0.2 mm on the default printerno: it is the printer's
deg, radangledegrees; radians (pi is a number word, so a turn is 360deg or 2 pi rad)no
%plain fraction50% is 0.5 everywhere (cover="100%", buried="20%..50%")no

Sizes in the library are written in dmm, so at OpenLOCK's 25.4 mm square a 7dmm wall prints 5.08 mm thick and a 4.5dmm leaf 3.27 mm long, and a stone that must fit a 28 mm miniature is written in mm. Write sq or a share to follow the grid exactly. Densities (perSquare=45) follow the square; counts, words and switches never change.

What scales

Every size written in dmm or sq scales with the system, like a photocopy. The hidden printability floors never shrink: they come from the printer profile, library/printers/default.dtile, written in printed units:

dharmatiles version="1.0.0"

printer default {
    line     "0.45mm"       // one extruded line: the thinnest wall that prints
    layer    "0.2mm"        // one layer
    overhang "55deg"        // what every element aims for, degrees from vertical
    steepest "65deg"        // small patches up to here
    gap      "0.2mm"        // the narrowest gap that stays open
}

Other profiles sit beside it in library/printers/ (fine, and a machine by brand and model, bambu/x1c), and your own in a printers/ folder beside your tiles; --printer chooses one. A profile holds the printer's floors, and for a machine its bed and filaments (see Printers): the base system is chosen with --system, and edge and corner rounding belong to materials. Elements apply the floors after scaling, so a scaled blade, leaf or branch is never thinner than what prints.

Writing a unit

  • A unit goes right after its number and multiplies it: 2layer is 0.4 mm on the default printer, 0.5sq is half a square, 2 pi rad is a full turn. House style writes no space (4.5dmm, as 50% already is); a spaced 4.5 dmm still reads.
  • A digit followed by letters is always a number and a unit, since plain names can't start with a digit. An unknown suffix, 2foot, is dt::unit: “foot is not a unit”, listing the units.
  • A bare 0 is the same in every unit and fits any of them.
  • As a coordinate's second argument a unit divides instead: d($region, mm) is the distance in from the edge counted in printed millimetres, a plain number (section 6).
  • % on its own is a plain fraction. It is a length only inside a point, "(50%, 2sq)", where the frame gives it a size, and a coordinate's unit divides by the frame's own size: x($region, %) is 0 at the region's west edge and 1 at its east. An angle is always deg or rad: polar($tile, 40%, 90deg).
  • Printer files take printed units only: line "0.45mm", layer "0.2mm", overhang "55deg". sq, dmm and layer have no meaning there and are refused.

The kind check

Lengths, angles and plain numbers are checked apart, before anything is built. A control wants a kind, and a formula has the kind its parts give it:

WrittenKindWhy

$groundHeight + $xerrorsquares counted are plain; write $groundHeight + 4dmm * $x

A mismatch is dt::type, a number missing its unit dt::unit; both point at the value and say what to write. A let holds whatever its formula is, so let reach "3dmm" is a length wherever it is read and let n 3 a plain number. A param takes its kind from the control it fills (section 9).

5. Heights: tops and pins

Heights are written one way everywhere: lengths above zero, the top of the base. A height is a length (top="8dmm"), a $ name from the library's heights, or a formula of them. height is a different word: how tall a thing stands above what it stands on, a length (thickness "7dmm", stones height="2.2dmm .. 5.2dmm") or a word (wall … height full, up to $wallHeight).

A height may use numbers with units, plain and $ names, $x and $y (squares, plain), $d and $a (fractions), $bottom (the surface under this body, or under the thing), + - * /, a range in brackets anywhere ($groundHeight + [1dmm .. 2dmm]), the coordinate calls (section 6), and the functions sin and cos (of an angle), abs, min, max, clamp and smooth. Kinds are checked (section 4): $groundHeight + $x adds squares to a length and is refused.

A body of the stack (dirt, water, cliff, flagstones, planks) says how high it may be with its top=, a band: a single height fixes the surface, a range leaves it room. A pin holds the band to a height at a place; where pins overlap the later one wins, and the library's defaults (below) are read first. The stack is written bottom up: base first, the land in order, things and grass where you want them, water after the ground it fills over and the rocks and reeds it should ring, and before the grass that should see its shore. The stack is built in the order it is written.

dharmatiles version="1.0.0"

tile size="1x1" {
    point knoll "(0.28sq, 0.28sq)"
    region banks { within "11.5dmm" of=center }
    stack {
        base
        dirt top="[$groundHeight .. $groundHeight + 2.5dmm]" {
            slope "30deg"                                  // how steeply this dirt lies; 24deg by default
            pin top="$groundHeight + 4dmm" at=knoll
        }
        water at=banks                                // fills over the ground listed above it
        grass at=banks                                // listed after the water: keeps off the wet ground
    }
}

Defaults. library/parts/edges.dtile also holds the tops and pins every body starts with, read before the tile's own lines:

dharmatiles version="1.0.0"

defaults {
    dirt  top="[$groundHeight .. $groundHeight + 1dmm]" { pin top="$dirtEdgeHeight" at=edges }
    cliff top="$dirtEdgeHeight + 35dmm"
    flagstones top="$floorHeight"                     { pin top="$floorEdgeHeight" at=edges }
    planks top="$floorHeight"                         { pin top="$floorEdgeHeight" at=edges }
    water top="[$waterSurfaceHeight - 1.9dmm .. $waterSurfaceHeight + 3dmm]" { pin top="$waterEdgeHeight" at=edges }
}

A tile's own top= replaces the default top, and its pins win over the default pin wherever they overlap. The dirt default applies to the first dirt only, so a second dirt laid over what is under it (dirt top="$bottom + [0.6dmm .. 1.2dmm]") is not pulled to the rim; the water, flagstones and planks defaults apply to every water and every floor. dharmatiles check --explain lists every default applied and where it came from, each override (override $waterBedHeight 0.4dmm → 0.8dmm), each pin's share of its place, and the region tree (section 6).

What check does with them. Besides reading the names and kinds, check solves each body's band on a lattice (no meshes, tens of milliseconds): the pins hold the band exactly where they are, dirt eases back toward the others no steeper than its slope (water settles over 9 mm; cliffs and floors do not ease: their stones and slabs step), and the result is the band the body fills. It refuses what cannot be solved and notes what looks wrong (the codes are in Errors). build solves the same bands again on the build's own lattice and fills them: a dirt draws hills in its band, a water draws its waves inside it, and a floor draws each slab's or board's height and tilt inside it. A cliff draws its stones inside its band, as a floor draws its slabs. A tree's top= is its height: $bottom is the ground at its foot, so top="$bottom + 40dmm" is 40 design millimetres tall wherever it stands and top="$groundHeight + 40dmm" reaches that height above zero. A tree's top is a cloud like a band's: each branch tip rolls smoothly inside it and the crown stays under its high.

A complete tile that builds:

dharmatiles version="1.0.0"

tile size="1x1" seed=62 {
    point crossing "(0.65sq, 0.5sq)"
    line stream wobble="0.5dmm" { through westCenter eastCenter }
    region banks { within "11.5dmm" of=stream }
    region bed   { within "1.5dmm" of=stream }
    stack {
        base
        dirt {
            pin top="[$waterBedHeight .. $groundHeight + 1dmm]" at=banks       // anywhere from the bed to the land
            pin top="[$waterBedHeight .. $waterBedHeight + 0.3dmm]" at=bed     // later, so it wins in the bed
        }
        rock size="6dmm .. 10dmm" at=crossing
        water top="[$waterSurfaceHeight - 1.9dmm .. $waterSurfaceHeight + 3dmm]" at=banks
        grass
    }
}

Clouds: a top with odds

A top may be a cloud: a low surface, a high surface and one weighting that says how often each height between them comes up. Write a weighted range in the top: top="$groundHeight + low(0dmm .. 3dmm)" is dirt between the ground height and 3dmm over it, mostly low with a few rises. A plain range, [a .. b], is a cloud with every height equally likely, and builds exactly as it always did.

The body supplies a roll from 0 to 1 at each point and the weighting places it between low and high. How neighbouring rolls relate is the element's own business: dirt and water roll one smooth surface (hills, waves), flagstones, planks and cliff draw their slabs and stacks of stones from one smooth heaved surface, so neighbours are alike. A weighting other than flat reads the roll by its rank over the body's points, so even a smooth field's heights come up as often as the weighting says. Rolls are fixed by the tile's seed and are the same on any number of threads. A tree rolls one smooth field of rolls over its branch tips, ranked through the weighting, so neighbouring tips are alike and the crown stays under the cloud's high; a rock (and stone, boulder, pebble) rolls one smooth field of rolls over the tile's stones, ranked through the weighting, and stands its peak at the cloud worked out at its middle (rock top="$bottom + [4dmm .. 9dmm]"; see rock).

  • A pin replaces the cloud where it holds. Away from it the surface eases back into the cloud the way the body eases: dirt no steeper than its slope, water over 9 mm, cliffs and floors step. A pin's own top may be a cloud (pin top="$waterBedHeight + high(0dmm .. 0.3dmm)"), rolled with the body's roll; where pins overlap the later one wins. The library's rim pin is the edge height, so the top never leaves its cloud or its pins.
  • Arithmetic on a cloud keeps two surfaces and one weighting. + - * / by a number, or a formula that is a number at the point, shifts or stretches both surfaces and keeps the weighting; min, max, clamp and smooth of one cloud and numbers act on the surfaces (min(high(0dmm .. 20dmm), 10dmm) is high(0dmm .. 10dmm): no shelf).
  • A negative factor swaps low and high at the points where it is negative, and the weighting turns round with them, so low is always the lower surface: 10dmm - high(0dmm .. 4dmm) is low(6dmm .. 10dmm), point by point.
  • Two ranges are two rolls. A sum or difference of two ranges, with odds or without (low(0dmm .. 2dmm) + [0dmm .. 2dmm], [0dmm .. 2dmm] + [0dmm .. 2dmm]), spans the interval of the sum and has the odds of two independent rolls: the second is a triangle over 0dmm .. 4dmm, most often near 2dmm. The body still rolls one number at each point, in those odds.
  • Refused, with dt::cloud: a cloud multiplied or divided by a range, dividing by a cloud or by a range, sin, cos or abs of a cloud (they can fold low and high over each other), a cloud at the end of a range. The help shows the rewrite.
  • A weighting's extra numbers stay plain: low(0dmm .. 3dmm, 11). A list is a cloud of the heights written ([0dmm:3, 2dmm, 4dmm:1]).
dharmatiles version="1.0.0"

tile size="1x1" seed=21 {
    stack {
        base
        dirt top="$groundHeight + low(0dmm .. 3dmm)" bumpSize="12dmm"
    }
}

The edge contract

Every tile also reads library/parts/edges.dtile, without a use line. Its defaults block (above) gives the first dirt, and every water and floor, a top and a pin at the tile's edges, so that neighbours butt with no step. So any dirt tile butts any other with no step, and any two water tiles meet in the same wave. A pin the tile writes later wins over a default where they overlap. See edges.

6. Coordinates, points, lines and regions

A tile is rows and columns. Every position counts from the north-west corner: across the row from the west edge, then down the column from the north edge. A size="2x1" tile is 2 squares across and 1 down.

Coordinates

A coordinate is a function of a region and a unit. x and y are where a point is (across, down), d is how far in from the edge, a is how far round. The unit says what to count in, and divides, so the result is a plain number.

WrittenMeans
x($tile, sq), y($tile, sq)squares from the tile's north-west corner ($x and $y for short)
x($region, sq), y($region, sq)squares from the region's own north-west corner
x($region, %), y($region, %)0 at the west (north) edge of the region's bounding box and 1 at its east (south): across the region by share. On $tile it scales with the tile's size, so a 2×2 and a 4×4 give different values the same distance from the corner; anything that must meet across tiles, like the tide, stays in sq
d($region, %)0 wherever deepest in the interior, 1 right at the edge, scaled by the deepest part of each separate piece (a puddle beside a lake has its own 0). A region thinner than a cell is given a depth of one cell ($d for short)
d($region, mm)the distance in from the edge in printed millimetres: 0 at the edge, rising inward
a($region, %), a($region, deg)how far round the region: 0 at east, turning towards the south as the page reads (90deg is straight down), a full turn 1 or 360deg; so a wave round it is sin(360deg * $a) ($a for short)

The shorthands $x and $y are always the tile's, so neighbouring tiles meet; $d and $a are always the thing's own region. In a region with a hole (land round a pond) “round” has no meaning for $a, and a thing that cannot read a name (a rock sets only $region) is refused at check, at the spot.

dharmatiles version="1.0.0"

tile size="2x1" seed=4 {
    region hill { within "[8dmm .. 14dmm]" of=center }
    stack {
        base
        // a dome over the hill's own region: 3dmm higher where deepest, level at its rim
        dirt at=hill top="$groundHeight + 3dmm * (1 - $d * $d)"
        dirt top="$groundHeight + 0.6dmm * sin(360deg * $x / 2)"      // a swell along the tile
    }
}

Points

A point has two halves, across and down, written in parentheses and quoted, each half a length: "(0.65sq, 1sq)". A half may be in any length unit, or a %, which here is a length: the share of the frame's width (or height), "(50%, 0.25sq)". A tuple is a point in the frame it is written in: the tile, unless it sits in a pin of a body that acts in a named region, where it is that region's own corner.

WrittenMeans
"(0.65sq, 1sq)"across 0.65 squares from the west edge, down 1 square from the north edge
"(50%, 2dmm)"half way across, 2 design millimetres down
point($tile, 25%, 75%)the frame always named: $tile, $region (the region the point sits in) or parent($region), then across and down
polar($tile, 40%, 90deg)out from the frame's deepest point by a share of its depth, at an angle round it (0 east, 90deg straight down)
north, southEast… a point's namecorner and edge words, the built-in names and declared points, unchanged

A point outside the tile, or outside the region it is written in, is dt::point at check, with the box it should be inside. In a line's through and a region's fill either half may be a range, drawn once from the tile seed ("(0sq .. 0.1sq, 0.3sq .. 0.5sq)", or a weighting such as bell(…)), keyed by the line's name and the point's place in the list, so another seed draws another line and editing one point moves no other. A thing's at= is one fixed point, not a range. A part, which has no tile of its own, writes points the same way and they are worked out at each place it is called.

ThingWritten asMeans
Tile sizesize="2x1"Columns first. Default "1x1".
Edgenorth, south, east, westFor a thing, a point: the middle of that edge. For a wall, surface or scatter, a line: that edge.
Edge pathat="north west"Several edges in order, quoted. Two edges meeting make a corner.
CornernorthWestCorner, southEastCorner, …A point at that corner.

A wall or cliff on a tile edge always stands inside the tile, its outer face flush with the edge. That is the DungeonBlocks slab standard, and it means an author never has to work out which side of a line a wall is on.

Lines

A drawn line runs through points. With a width it is a strip, and a dirt, grass or cliff at= it fills the strip (within half the width, wobble included), and a scatter reaches half the width either side unless it writes reach. A surface along a line with no width, or along a tile edge, is dt::type. wobble lets it wander up to that far off its points.

line trail width="9dmm" wobble="3dmm" { through south "(0.65sq, 0sq)" north }

An element along a drawn line takes side=left, right or centre (the default), as you walk the line. side= along a tile edge is an error, because on an edge a wall always stands inside.

Regions

The whole tile is the default area, so an undivided tile needs no region. A region exists when lines divide the tile. It is the paint-bucket model: name the lines that bound it, then drop one or more fill points.

region verge { boundedBy trail; fill "(0.15sq, 0.5sq)"; fill "(0.85sq, 0.5sq)" }

Several fill points on different sides of a line join areas without union, intersection or difference. Elements act inside a region with at=verge.

Every thing makes a region

Every frame is a region, and regions nest. A point or a line says where a thing goes; the thing's size makes its region: a tree's crown round its point, a rock's disc, a wall's strip along its line, a scatter's area. A $region is the region of the thing being built (at a declaration, the region the declaration sits in), $tile is the root, and parent($region) is the region containing it.

  • The tile has no parent: parent($tile) is dt::region “the tile has no parent”.
  • A named region's parent is the smallest strictly larger region that holds its first fill point, else the tile. Regions that only share a line, like a pool and its bank, are siblings.
  • A scatter is a region of its own, its at= area (or the tile); the things it places are its children: a tree in a scatter at tile level has the scatter, then $tile.
  • A body, coat or scatter with no region of its own acts in its at= region, else the tile.

A region is its own kind of value: it goes to parent() and to the coordinate calls, never to arithmetic. check refuses a read of a parent that is not there before any build, at the exact spot. dharmatiles check --explain prints the tree:

regions
  $tile: tile, parent none
    scatter (entry 2): scatter, parent $tile
      tree (entry 2, thing 1): placed disc, 18.0 mm across, parent scatter (entry 2)
      rock (entry 2, thing 2): placed disc, 6.0 mm across, parent scatter (entry 2)
  entry 1 `dirt` acts in $tile
  entry 2 `scatter` acts in scatter (entry 2)

Places by name

A place is a point, a line or a region, all flat: they say where, never how high. Every tile has them built in, named in camelCase:

KindDeclaredBuilt in on every tile
pointpoint knoll "(0.28sq, 0.72sq)"northWestCorner northCenter northEastCorner westCenter center eastCenter southWestCorner southCenter southEastCorner
lineline stream wobble="4dmm" { through … }, closed=#true for a loopnorthEdge eastEdge southEdge westEdge, and edges for all four
regionregion meadow { … }the whole tile is what no at= means

A place is written as a name or as a literal point "(x, y)". A region is its fill points and its discs less what it excepts:

region banks { within "4.5dmm" of=stream }                // a disc round a point, a strip beside a line, a ring round a region
region verge { except path }                              // a region that only excepts is the whole tile less those
region knoll { boundedBy foot; fill center }             // the paint bucket

One place word, at=, says where an entry goes, and it takes any place: a point, a line or a region. Each element takes the kinds that mean something to it and refuses the others with dt::type and a help line: a body, grass or reeds fills a region (a body or grass may also follow a line); a wall follows a line; a thing stands at a point or fills a region, and given a line it is refused (a line has no one place on it: write a scatter); a scatter fills a region or spreads along a line, within reach either side of it, and given a point it is refused (write a region round it, within "5dmm" of=knoll). With no at= an entry covers the whole tile. within, except and boundedBy build places; they never use one. See point, line and region.

7. Placement and scatter

Place words

One word, at=, names the place, and side= adjusts a line. Each element page lists the kinds of place it takes.

WordTakesMeans
at= a regiona region nameActs only inside that region. Default: the whole tile.
at= a linea line, an edge or an edge pathBuilt or spread along it. On a tile edge, always inside.
at= a pointa point ("(0.65sq, 1sq)", point(…), polar(…)), a point's name, or a corner or edge wordCentred there. No at=: anywhere in the area.
at="foot(cliff)"foot( cliff, wall, rock or tree ), quotedThe band at the foot of that kind of thing, where a scatter gathers. reach= says how far out.
side=left, right or centreAlong a drawn line, which side the element stands, as you walk the line. Not on a tile edge.

A wall must have at= a line; a cliff needs it for the edge forms (run, corner, escarpment) but not the free-standing ones. Surfaces take a region and usually a line; things take a point or a region. An entry has one place: a second at= is dt::duplicate.

One thing

Things share one vocabulary. A rock (and stone, boulder, pebble), a tree and a flower are placed the same way, with at= a point or a region they stand in, and sized the same way, by size=, which takes a number, a range or any weighting (size="low(1dmm .. 6dmm, 11)"); a tree's size is its height and a flower's the width across its petals. Many of them are a scatter whose children are things: scatter at=meadow perSquare=4 { flower size="4dmm .. 6dmm" }. A scatter holds rocks, flowers and trees, alone or mixed: each placed item picks its child by weight=, and one gap keeps every two things apart (trees are placed first, then rocks, then flowers); trees keep their crowns clear of one another, and scatter at=road count=3 { tree } is a row of trees along a line. A thing is one of itself. How many is never its own control: tree count=3 is an error whose help says to use a scatter. With no at= a thing goes anywhere in its area. Either way its footprint is kept inside the tile and clear of other solids, nudged inward rather than clipped.

scatter

More than one of a thing is a scatter. It says how many and where; its children say what.

ControlTakesWhat you get
countnumber, or a weighted rangeHow many, in total.
perSquarenumber, or a weighted rangeHow many per square of the area, or per square of length along a line.
reacha lengthWith at="foot(…)": how far out from the foot.
clumpsper squareGathers them into clumps. Default: spread evenly.
gapa lengthLeast space between neighbours.
child weight=numberShare of the mix when there are several children. Default: equal.

A scatter must have exactly one of count and perSquare; reach needs at="foot(…)". A scatter inside a surface (dirt { scatter … }) lands on that surface.

Stack order

The stack is built in the order it is listed. Each entry stands on the terrain as laid so far, and what is listed after it is laid over or beside it. Land bodies are laid in stack order, each the higher of what is below and its own top: a dirt along a path, listed after the whole-tile dirt, takes the higher of the two there. A dirt listed after a rock, a tree, a flower or a scatter of them is built after them: it lies on the tops of rocks where they are flatter than its maxSlope, banks up to a trunk or a stone (a rise is no drop), and covers a flower's foot, as written. A tree's crown is never a surface for dirt. A dirt listed before them is laid first, and they stand on it (a rock beds into it). Grass grows round what is listed before it, so list the grass after the rocks, trees and flowers it should grow round; the same goes for water, which fills over the ground listed above it and sees the rocks and reeds listed above it (each sends its own chop). What is listed after the water stands in it or on its shore and reads it: a rock stands in the pool, and grass keeps off the wet ground. A dirt or ground listed after the water lies over it: where its top is higher than the water the earth shows, where it is lower the water stays. Water is built where it is listed, like every other layer; nothing is written about it last.

The plan refuses what the listed order cannot satisfy, with dt::order and the entry's place, and never reorders to cure it: a tree, grass or wall listed before the first ground or dirt it stands on, a thing that reads another kind (grass that needs rocks) with the first of that kind listed after it, a floor listed before a surface it lies on. Two things are placed by what they are, not by where they are written: the lift (the one solid the surfaces make together) comes right after the last surface, water or floor, and base, which reads the finished tile, is built last.

9. Parts: use, define, param

Parts files hold definitions that tiles bring in by name. A use line names the file and the definitions it brings in, so a reader knows where every name came from:

use "parts/grass" lawn long-grass

A bare path such as "parts/grass" is the bundled library, and "lib:parts/grass" says so explicitly. "./mine" or "../shared/x" is a file in the author's project. Anything else is an error.

A define has param lines and one stack. It is called like an element; its params are set as properties, and a place (at=) passes through to the elements inside it. A definition can call another. A definition whose stack is one thing is itself a thing, so it can be placed with at= or scattered: scatter count=2 { oak }. Definitions that call each other in a loop are an error (dt::loop).

dharmatiles version="1.0.0"

// library/parts/grass.dtile
define lawn {
    param length "3.5dmm .. 6.5dmm"   // blade length along the ground
    param height "1.5dmm .. 2dmm"     // how tall a blade stands over the ground
    param clearings 0                 // patches of bare earth per square
    param cover "100%"                // share of the ground grassed over

    stack {
        grass length=length height=height clearings=clearings cover=cover
    }
}

// Long, tall blades: the species of 2x2-grass-tree.
define long-grass {
    stack {
        lawn length="5dmm .. 9dmm" height="2dmm .. 3dmm"
    }
}

A param takes its kind from its default or, with none, from the control it fills: param length "3.5dmm .. 6.5dmm" is a length, param clearings 0 a plain number, and a caller that writes length=5 gets dt::unit asking for 5dmm. A param without a default must be given by the caller. A tile has no params. Expert controls live in parts files:

dharmatiles version="1.0.0"

// library/parts/trees.dtile
define oak {
    stack {
        tree top="$bottom + 59dmm" {
            trunk height="18dmm"
            crown width="44dmm" clumps=60 shape=wide
            branch split="34deg" eagerness=0.6 target=0.25 balance=0.8 exponent=3 minRadius="0.9dmm"
        }
    }
}

A call's top= is the tree's. A tile places one oak as oak at="(1sq, 1sq)" top="$bottom + 60dmm", or several as scatter count=2 { oak }.

10. Errors

Every mistake gets a message with a stable code (such as dt::unit), the line it is on with the spot underlined, and a hint that says what to write instead. The program reads on past a mistake, so all of a file's mistakes come together. dharmatiles check my-tile.dtile reports them without building (it takes --system, --printer and --seed like build, so a mistake that only shows on OpenLOCK is caught too); the preview shows them beside the tile. 11. Worked examples

Whole tiles, each with what it shows. Every one builds as written: copy it into a .dtile file and run dharmatiles preview on it.

A grass meadow with one tree

dharmatiles version="1.0.0"

// library/tiles/ground/2x2-grass-tree.dtile
// A 2×2 grass meadow with one tree.

use "parts/grass" long-grass

tile size="2x2" seed=84 {
    stack {
        base
        dirt clods=none
        tree top="$bottom + 49dmm" {     // anywhere on the tile; or at="(1sq, 1sq)"
            trunk height="30dmm"             // bare trunk below the crown
            crown width="30dmm" clumps=32 shape=round branching=normal
            leaf length="4.5dmm" width="3dmm"
        }
        long-grass                      // listed after the tree, so it grows round the trunk
    }
}
  • No region: the whole tile is the default area.
  • The tree has no at=, so it goes anywhere on the tile. at="(1sq, 1sq)" would put it in the middle.
  • The grass is listed after the tree, so it grows round the trunk; listed before it, the tree would stand in the grass.
  • long-grass grows standing blades.

A fieldstone wall turning a corner

dharmatiles version="1.0.0"

// library/tiles/walls/1x1-wall-fieldstone-corner.dtile
use "parts/grass" lawn

tile size="1x1" seed=64 {
    stack {
        base
        dirt                                // bare earth at the ground height

        // Along the north edge, then the west edge.  On a tile edge a
        // wall always stands inside, its outer face flush with the edge.
        wall at="north west" style=fieldstone seed=15 {
            height full                     // up to $wallHeight (33.1dmm)
            thickness "7dmm"
            coping loose                    // or: on-edge

            // fieldstone's own defaults, written out to show them
            stones height="2.2dmm .. 5.2dmm" length="5dmm .. 16dmm"
            joints width="0dmm" depth="2.8dmm"        // how deep the gaps between stones look
            edges rounding="1.3dmm .. 2.6dmm"       // worn corners
        }

        lawn
    }
}
  • Two edges in at= make a corner.
  • The wall's seed=15 pins its stones while the tile seed varies everything else.
  • On OpenLOCK, the 7dmm thickness and the stone sizes all shrink with the square.

A cliff run

dharmatiles version="1.0.0"

// library/tiles/cliffs/2x1-cliff.dtile
tile size="2x1" seed=1 {
    about """
        Rock band against the north edge. Both ends finish in the
        standard end section, so runs butt end to end.
        """

    region crag  { within "[10dmm .. 20dmm]" of=northEdge }
    region apron { within "6.5dmm" of=crag }

    stack {
        base
        dirt top="$dirtEdgeHeight" {
            pin top="[$dirtEdgeHeight .. $dirtEdgeHeight + 3.5dmm]" at=apron   // the bank, drawn
            pin top="$dirtEdgeHeight" at=edges
            scatter perSquare=45 { pebble size="1dmm .. 2.2dmm" buried="20%..50%" }
        }

        cliff top="$dirtEdgeHeight + 35dmm" at=crag {
            rock mixed                  // or: columns, blocks, slabs
            stoneSize massive          // or: rubble, broken
            shattered patches=3 width="5dmm .. 10dmm"
        }
        dirt top="$bottom + [0.6dmm .. 1.2dmm]" at=crag   // dirt on the cliff's top

        // scree: fallen stones gathered at the cliff's foot
        scatter at="foot(cliff)" perSquare=55 reach="4dmm" { stone size="low(1dmm .. 6dmm, 11)" }
        scatter at="foot(cliff)" perSquare=2.5 { boulder size="4.5dmm .. 8dmm" }
    }
}
  • The dirt is listed before the cliff and still banks at="foot(cliff)". Its pebbles are scattered on the dirt.
  • Scree is stones and boulders scattered against the cliff; they take their fragment shapes from the cliff's rock.
  • $bottom on the second dirt is the cliff's top: it lies 0.6 to 1.2 design millimetres over it.

A divided tile: grass, a path and rocks

A path of bare dirt winding up a 1×2 tile through grass, with rocks beside it: lines, regions and at= together.

dharmatiles version="1.0.0"

use "parts/grass" lawn

tile size="1x2" seed=7 {

    // From the middle of the south edge to the middle of the north edge,
    // 9 design millimetres wide, wandering up to 3 off its points.
    line trail width="9dmm" wobble="3dmm" { through south "(0.65sq, 1sq)" north }

    // Everything beside the path: one fill point on each side of it.
    region verge { boundedBy trail; fill "(0.15sq, 1sq)"; fill "(0.85sq, 1sq)" }

    stack {
        dirt                                    // the whole tile, at the ground height
        dirt at=trail                        // the path, a second dirt along it

        scatter at=verge count=5 {
            rock size="4dmm .. 10dmm" shape=rounded buried="30%"   // shape: or angular, flat
        }

        lawn at=verge cover="85%"
    }
}
  • The second dirt is laid after the first along the path; each land body is the higher of what is below it and its own top.
  • verge is the tile less the path: one fill point on each side of the line. Points count down from the north, so (0.65sq, 1sq) is a square down from the north edge, half way along a 1×2 tile.

Rules of the language

  • A tile is a declarative document, not a program: KDL v2 underneath, saved as a .dtile file.
  • A document starts with dharmatiles version=…, once, first; its major part is the format, and this program reads format 1 only. A document with no header is format 0 and is refused (dt::format-0). A format newer than the program reads is refused.
  • Every length is written with its unit and every angle with deg or rad; a bare number is a count, a density or a fraction. dmm is 1/35 of a square and scales with the system, as sq does; mm, in and layer are printed lengths and never scale. A mismatch of kinds is refused before any build (dt::type, dt::unit).
  • % is a plain fraction (50% is 0.5); it is a length only inside a point, and it divides as a coordinate's unit.
  • A name starting with $ is read from the context every formula is called with; a plain name is declared by a let or param where it is written. let $name adds to the context, override $name replaces a value for its block, and neither may name a $ name an element sets ($x $y $d $a $bottom $region $tile). A plain name is declared once and may not be a word of the language.
  • A formula reads only the names its element sets: a body reads all of them, a tree reads $bottom and $region; check refuses the rest before any build.
  • Positions count from the north-west corner: across, then down. A point is "(across, down)", with units, in the frame it is written in; point($tile, …) and polar($tile, …) name their frame.
  • Every frame is a region and regions nest: the tile has no parent, a scatter is a region holding the things it places, and a read of a parent that is not there is refused at check.
  • Ranges, percents, units and points are quoted: size="6dmm .. 10dmm", cover="35%".
  • A plain range is flat, on every element. A weighting is written round it, size="low(6dmm .. 10dmm, 3)", and its extra numbers are plain; every range in a value is its own draw; a weighted range on a top is a cloud; a let name holds a distribution.
  • The whole tile is the default area. A region is flat: its fill points and its within discs, less what it excepts. One word, at=, names any place (a point, a line or a region), and each element refuses the kinds it cannot use with dt::type: a body or grass fills a region or follows a line, a scatter fills a region or spreads along a line (never a point), a thing stands at a point or fills a region. foot(cliff) is the band at that kind's foot.
  • A stack is written bottom up: base first, the land in order, water after the ground and the rocks, before the grass. Heights are lengths above zero; a pin is exact where it is and the later pin wins; the library's defaults are read before the tile.
  • Every control is camelCase, perSquare=55, not per-square=55.
  • Stack order is build order: every entry is built in the order it is listed, standing on the terrain laid so far, and the plan refuses (dt::order) what that order cannot satisfy rather than reorder it. Land bodies are laid in stack order, each the higher of what is below it and its own top.
  • Character controls are words that stand for documented numbers; a number is always accepted too.
  • A wall or cliff on a tile edge stands inside the tile.
  • scatter places many things; a thing on its own is one, placed with at=. With no at= a thing goes anywhere in its area, kept inside the tile and never clipped.
  • Water fills its area up to its top; the shoreline comes from the dirt beneath.
  • The library's heights ($groundHeight, $dirtEdgeHeight, $waterSurfaceHeight, $wallHeight and the rest) are always there.
  • z = 0 is the top of the base; the base owns everything below it.
  • Materials are named in the document and given colours separately, by a palette.
  • Controls sit on the element's line as properties, or as child lines.
