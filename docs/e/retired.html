What to do

Broken, then fixed

The rule

A let with a body has param lines and either one entry written bare or one stack. The body says what it names: one bare entry that is an unplaced thing (let oak { tree … }) names a thing, so it can be placed with at= or scattered (scatter count=2 { oak }); any other bare entry, and every stack, names a layer. Several entries are written in a stack, which is always a layer. It is called like an element; its params are set as properties, and a place (at=) passes through to the elements inside it. A definition can call another. Definitions that call each other in a loop are an error (dt::loop). A let has a value or a body, never both, and a body is never empty. The old word for this was define: it is refused (dt::retired) with the fix of writing let over it.
