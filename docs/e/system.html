Error code · a mistake in the document

dt::system

The build target is not one the program knows.

What to do

Use db (DungeonBlocks) or ol (OpenLOCK).

The rule

On a print list or a map the chip names the printer that document uses (Bambu Lab X1 · this map), read from the document as it is now, as the status line does; its card changes that document's printer, and Undo takes it back. Elsewhere the chip at the right of the title bar names what every build is for: the base system (DungeonBlocks or OpenLOCK) and the printer profile, such as DungeonBlocks · default. Click it to change either. The tile you are looking at, and every other tile you have built, builds again for the new target; the gate's angles and the numbers in the record are the chosen printer's. The choice is remembered in $DT_HOME (else ~/dharmatiles) for the next run; --system and --printer on the command line start the run on another one. Each printer is listed by the squares that fit its bed (6 × 6 squares · 1 colour · 220 × 220 mm) and drawn at one scale with those squares in it, using the square of the base system chosen above (35 mm for DungeonBlocks, 25.4 mm for OpenLOCK); choosing the other system redraws every bed. The slicer imports are one menu, Import from a slicer. The printers are the library's (library/printers/) and your own: a printers/ folder beside your tiles, one .dtile file each, named like the file (see Printing and Printers, where a profile is also a machine, by brand and model, such as bambu/x1c). There is no both: one build is one target. With a print list or a map open, the chip names that document's own printer (Bambu Lab X1 Carbon · this map), and choosing a printer in its card changes that document's plates line, as its plates panel does; the base system there stays the one tiles build for.
