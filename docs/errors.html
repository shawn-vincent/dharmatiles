Error codes

Every message the program prints carries a code, such as dt::type, and an address that lands on its own page here: what happened, what to do, a broken document and its fix, and a link on to the rule in the guide.

Every code

An error shows its code, then the address of its page (explain: …/e/type) and the command that prints the same words from your own copy of the docs (dharmatiles explain dt::type). In the editor, a message with a code has an Explain link that opens the copy served with the program. The table is written from the program’s list of codes, so a new code appears here when it is added. The codes whose rule has no other home are explained below the table; the rest are explained in the section the code’s own page links to.

Controls and lines

The mistakes in how a line is written, before what it says is checked.

dt::choice
A control that takes one of a few words (clods some, leaves bare) was given a word it does not have. The message lists the words the control takes.
dt::duplicate
A control is written twice on one line, top set twice for example. One of them would win without a word, so the document is refused: keep one.
dt::expert
Some controls are an element’s inner workings, kept for the library’s own tiles. A tile may not write them; the element’s page lists the controls a tile may.
dt::missing-name
let, point, line, region, define and param each need a name straight after the keyword.
dt::unknown-node
A line this kind of document does not hold at this place: a plates line holds pin lines and nothing else, a tile holds the nodes of section 1. The message says what is allowed there.

Definitions and expansion

Mistakes found when the program reads a whole tile, its parts and its definitions together.

dt::loop
Definitions call each other, or themselves, more deeply than the program follows. A definition may build on others, never round to itself.
dt::nesting
An entry was written inside one that does not take it. A pin goes inside a body, a thing inside a scatter; terrain goes in the stack.
dt::too-many
The stack expands to more than 10 000 entries once every definition is called and every scatter is counted. Scatter fewer things, or call a definition fewer times.
dt::not-yet
The word is in the language’s plan and is not built. The message says what to write instead.
dt::element
An element looked at its controls together and refused them, for a reason the message gives. The element’s page has its rules.
dt::no-tile
build was asked for a file with no tile in it: a parts file, a printer profile or a level file. These are only checked.

When the program fails

These are not mistakes in a document. The program shows them loudly, with what it knows, and a report of one is welcome (Errors says why they are kept apart from document mistakes).

dt::build
A build failed inside the program, not in the document. The message holds the cause.
dt::panic
The program stopped on a bug of its own while building. The message says what it was doing.
dt::payload
The editor’s page sent something the program could not read. Reloading the page is the first thing to try.
dt::internal
The program reached a state that the language’s own tables rule out, such as a body that has no body. It is a bug in the program.
dt::bug
An element reached a case it does not build. It is a bug in the program, and the message names the element.

Files

dt::source
A file could not be read: it is not there, or the program may not read it. The message has the path and the system’s reason.
dt::write
A file could not be written: the folder is missing, or the program may not write there. The message has the path and the reason.
