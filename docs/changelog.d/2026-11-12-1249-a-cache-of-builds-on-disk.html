• A cache of builds on disk: a finished build is kept in one cache folder ($DT_CACHE, else ~/Library/Caches/dharmatiles on macOS or $XDG_CACHE_HOME/dharmatiles; at most 4 GB, $DT_CACHE_LIMIT, least recently used out first) under a SHA-256 of everything the build read: the tile and every part it used (their text), the system, the printer profile’s numbers, the seed, the resolution (full or draft) and the engine, which is the version and a hash of the source that decides what a build makes, so a code change in a checkout can never serve old geometry. dharmatiles build and build --all read a build whose key is kept (the STL is still written, byte for byte the same; a second sweep of the library takes seconds) and --no-cache skips it; the preview opens a kept tile with no build, says passes · cached and From the cache in the status line and the messages, and Export reuses it. A damaged entry is reported (a warning in the messages and on the terminal), removed, and the build that replaces it is real. dharmatiles cache shows the folder, entries, size and limit; cache list lists them; cache clear empties it. Output and every hash are unchanged.
