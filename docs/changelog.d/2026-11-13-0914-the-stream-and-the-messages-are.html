• The stream and the messages are typed: every event of the event stream is one type in the program (StreamEvent) and every message another (MessageJson, with the gate’s, a build’s, a server failure’s and a mistake’s numbers as types of their own), generated into api.d.ts and checked by tsc against the page’s stream reader, the live updates, the messages store and the messages panel: a renamed or mis-cased field, or a resource the page has no case for, fails npm test (it showed NaN mm² in the record). One convention, said in api.rs: camelCase, except a message, which is its own document shared with the command line and an assistant and keeps snake_case everywhere. What stays untyped: the numbers of a check, an export, the plates and the inventory (no part of the page reads them by name) and a tile’s plan (one shape for a tile, another for a print list or a map, read by name in many places: its own piece of work).
