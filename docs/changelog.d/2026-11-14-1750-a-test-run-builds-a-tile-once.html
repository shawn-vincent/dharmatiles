• A test run builds a tile once: dt-eval’s integration tests are one test binary (the old files are modules of tests/tiles/) and build only through one memo, which keeps a build for everything it reads (the source’s content, the path and every field of Options); a scan test fails a test that builds without it unless a // fresh: comment says why (the cache, thread counts, a build compared with itself). The memo is a dev-only crate, dt-testkit, that dt-store’s and dharmatiles’ tests use too, and the library baseline and the release check that passes every library tile through the gate share their DungeonBlocks builds (cargo test --release -p dt-eval --test tiles -- --ignored the_library_builds_as_the_baseline_says).
