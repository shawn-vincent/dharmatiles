• A change is told as what changed: the places, the build target, the printers, the inventory and the list of tiles are each a resource with a revision of its own, and the program sends one on the event stream only when it changed (a new folder no longer resends the inventory or the tiles, and the page takes each into its own part of what it holds); the whole is sent once, when the page connects. The answer of a call that changes the places or a folder (adding or removing a place, making, renaming or trashing a folder, moving, copying or restoring a tile) no longer carries the list: it says the revision of the stream its change was told at, and the page waits for its stream to reach it (and says so, loudly, if it does not within five seconds), so a change has one way into the page and a new folder leaves the tiles and the inventory the very same objects. A map’s scene and its plates always name the same revision of the document. Reading a map remembers each tile’s size while its file is as it was, so an edit of a map answers in about a tenth of the time it did.
