• The browser engine and the site are typed: what the browser engine answers (the check, the build's record, the outline, a range's draw, a progress tick) is typed Rust, its fix is the program's own FixJson (made once, in dt-eval), and its TypeScript is generated into docs/assets/live/engine-wire.d.ts (a test fails when it is stale; cargo xtask regen writes it). The site's live scripts and site.js are checked by tsc against it (npm test in web/preview), so the hand-written shape of a check is gone. shots.json is one Rust type (Book), read back by the docs check and typed in the site from docs/assets/shots/shots.d.ts. The MCP server's tools each have an arguments struct that the call is read into and the inputSchema is made from, so the two cannot differ; an argument a tool does not take is refused, not ignored.
