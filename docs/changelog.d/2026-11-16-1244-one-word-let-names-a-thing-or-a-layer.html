• One word, let, names a value, a thing or a layer: define is gone. A let with a body names a thing or a layer, and its body says which: let oak { tree … }, one entry written bare, names a thing (it can be placed with at= or scattered), and let bank { stack { … } } names a layer, because a stack is always a layer, however many entries it holds. A bare body that is not an unplaced thing is a layer too. A part that was a thing by holding stack { rock } is now a layer: write it bare. A let has a value or a body, never both; a body is never empty, and holds one bare entry or a stack, not both; a body is written at the top level of a file. A file that still says define gets dt::retired at the word, with the fix that writes let over it (the refusal lasts one release, then define is an unknown word like any other). The editor asks the decoder, not a copy of its rules, what each name in the text is; a name it cannot settle is any. The element page for define is part of let, dt::define is dt::retired, and the thing view's request names a let (buildThing says a let of a value is not a thing). The library's oak is written bare.
