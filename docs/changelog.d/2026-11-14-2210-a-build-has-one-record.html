• A build has one record: a build's result is one type in the engine, TileRecord, with the gate's verdict and numbers as one AuditSummary (its repairs counted in one Repairs). dharmatiles build --json, the .build.json beside the STL and dharmatiles audit --json all print it. The editor keeps it and its gate message carries it, and the site's live tiles, the golden snapshots and the library baseline all read it; the page's TypeScript types are generated from the same structs. The JSON changes shape: target sits beside record, the repair counts sit under audit.repairs, stage_secs keeps build order as pairs, and cache is always {state, made_by, problems}. The overhang budget shown is now the one the gate judges by (the printer's or the band's share, whichever is larger), and a low build's failures are empty everywhere, not only in the CLI.
