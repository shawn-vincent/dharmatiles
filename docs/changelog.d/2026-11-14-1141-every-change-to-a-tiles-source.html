• Every change to a tile’s source is one edit engine, and names the node it changes: a control set, an entry added, hidden, moved or taken out, a line or region renamed, a clause written and a fix’s Change to… are all dt_doc::ops (Kind::Tile), beside the print list’s and the inventory’s, with one error type. Every node of a tile has an id made from the text (tile/stack/rock#2, tile/line shore, tile/stack/rock id=old-oak: a node that names itself keeps its id when others move), the check lists them, and an id the text does not have is refused in words instead of changing another node. Each edit works out the byte ranges it changes and writes only those, so comments, blank lines and your own layout stay. dharmatiles fix lays its fixes in the same way. The old byte-offset edit paths are gone.
