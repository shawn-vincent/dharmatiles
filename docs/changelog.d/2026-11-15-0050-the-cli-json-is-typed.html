• The command line's --json is typed: every report is one type that the program makes and its tests read by deserializing, and a mistake is the same record the page shows (code, message, file, line, column, help, fix, unexpected) in every report, so a build that panicked in cache previews now carries a whole mistake, not only a code and a message. A script reading it will notice: cache --json and cache previews --json are camelCase (limitBytes, totalS); plates --json and its .plates.json use the page's plan, kind and plate types (camelCase: otherColour, seedUsed, checkInventory, groupingCost, totalS), the plan's settings are flat beside its kinds, a kind no longer lists path, hash, nominal or estimate, each placed piece gains its list piece's id;printers import --json lists each slicer with its title and a model's keys are as before; and build --json, check --json and elements --json keep their keys. target.json and places.json are each one type; a places.json entry that is not valid UTF-8 is refused, not rewritten lossily.
