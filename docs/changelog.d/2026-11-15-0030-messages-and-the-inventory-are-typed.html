• Messages and the inventory are typed: what a message carries (data) is one type, MessageData, with a variant for each sort of message that has numbers (a check, a build, the gate, an export, plates, inventory lines, a diagnostic, a failure of the program's own), tagged by type; a message with none has null. A failure's causes and backtrace are typed too, and the page reads the variants instead of keys. The inventory's state and its rows are one type, InventoryState (absent, read, broken or unavailable), which the page reads in every snapshot and dharmatiles inventory --json list now writes: its JSON is camelCase like the page's and lists the pieces by seed (edited replaces edited_since_printing). Nothing rewrites JSON keys on the way out any more.
