• The editor runs in a web page with no program behind it: cargo xtask editor <out-dir> lays the editor page, the site's visual system and the engine out as static files; served by any static server and opened with ?host=worker, the page talks to the editor's service running in a web worker (the same verbs the program answers over HTTP) instead of to the program: open a library tile, change a control (the first change copies it into My tiles, in the page's own store), see the draft and the build, and save. A build's stages arrive as they happen. What the service does not answer yet (folders on a disk, the plates, the inventory, the maps' table, another build target, writing an STL) is refused in words by name, never answered empty. The program's own editor is unchanged. cargo xtask parity --service now also holds the worker's reading verbs, draft, snapshot and copy of a library tile.
