• One key for a tile, and one store of kept builds in the browser: the browser editor built a tile in its lane under a stand-in path while an export or a plate built it under its own, so the same tile was kept twice and an export never read the build already made. Every build of a tile now names the tile’s own path, so the lane’s build, an export and a plate’s piece are one entry. The builds the browser keeps are now one store, the engine’s own, held in IndexedDB between visits by a single small keeper: reload the editor and a tile you built reads from it instead of building again, and the site’s examples keep their drafts the same way. The site’s separate JavaScript store of drafts, with its own keys, encoding and eviction, is gone; drafts kept by the old store are not read and the old database is removed on the next visit (they were a cache: the examples draft again once).
