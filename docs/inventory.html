Inventory

The inventory remembers what you have printed, so a print list prints only what you lack. It is one file beside your tiles, a log with a line for each print, and every count you see is worked out from that log.

The file

The inventory is a KDL v2 document called inventory.dinv, in your tiles folder ($DT_HOME, else ~/dharmatiles) beside the tiles. It has its own extension because it is not a tile. Nothing is made until the first line is written: with no file there is no inventory yet, and every piece prints.

dharmatiles version="1.0.0"

inventory {
    print "lib:tiles/ground/1x1-grass"     seed=97 system=db colour=multi  result=ok     on="2026-11-09" hash="3c1f9a4e" from="crossing/plate-1"
    print "lib:tiles/ground/1x1-grass"     seed=12 system=db colour=multi  result=ok     on="2026-11-09" hash="3c1f9a4e" from="crossing/plate-1"
    print "lib:tiles/walls/1x1-wall-stone" seed=14 system=db colour=single result=ok     on="2026-11-09" hash="a07d22b1"
    print "lib:tiles/cliffs/2x1-cliff"     seed=4  system=db colour=multi  result=failed on="2026-11-09" hash="55e0c3d9" note="top layer stringing"
    print "lib:tiles/cliffs/2x1-cliff"     seed=4  system=db colour=multi  result=ok     on="2026-11-10" hash="55e0c3d9"
    gone  "lib:tiles/ground/1x1-grass"     seed=12 system=db colour=multi  on="2026-11-11" note="dropped on the floor"
    renamed "home:meadow" to="home:meadows/glade" on="2026-11-12"
}

The panel is a shelf: each tile is a row of cards, one per print, each a picture of the tile at that seed with the number on the shelf over it (×2), the seed, the colour and when it was last printed, and Gone and Reprint under it. Hover a card for the sentence (On the shelf: 1 · printed today · single colour · seed 9486); a date is today, 13 Nov this year and 13 Nov 2025 before, and the tile's full id is the tooltip of its name.

It is a log: a line is added for each print, each loss and each rename, and none is edited away. It stays hand-editable, and a mistake in it is shown at its text as in any document (seed missing, a system that is not db or ol, a date that is not a date), with a hint.

LineMeans
print "<tile>" seed= system= colour= result= on=A piece came off the printer. result is ok or failed. hash is the first eight hex digits of the tile document's hash when it was printed, from the print list and plate it came from, note anything you like. hash, from and note are optional.
gone "<tile>" seed= system= colour= on=One of that piece is lost or broken. It takes one away from what you have; the print line it came from stays.
renamed "<old>" to="<new>"A tile has another path now: its prints follow it. The editor writes one when it renames or moves a tile in My tiles, or a folder with tiles in it.

A tile is named lib:tiles/ground/1x1-grass for the library's, home:meadows/glade for one in your tiles folder, else by its path; the .dtile is left off. colour is single or multi.

What counts as the same piece

A piece is the same piece when its tile, seed, system and colour mode are the same.

  • Seed. Two seeds of one tile are two different pieces: that is what makes a piece yours.
  • System. DungeonBlocks and OpenLOCK never count for each other. Wherever the inventory is shown, system is a filter, and it starts as the target system of where you are: the chip in the title bar for the folder pills, the list's own system for the plates.
  • Colour mode. A multicolour piece is not the single-colour one. A multicolour piece wanted where you only own it in single colour reads have, single colour (a yellow stripe, the colour notes use; orange and red stay for overhang), and is left for you to decide: it still prints unless you leave it off.
  • Counts. Two prints of one piece are two. A failed line is kept, because it says what your printer does badly, and does not count. A gone line takes one away.
  • Edited since printing. If the tile's document hash is not the one recorded, the piece shows edited since printing. This is information only: it still counts as had.

Print lists and the inventory

A print list prints only what the inventory lacks. For each piece, the plates take the count in the list, less what you have of that exact piece (tile, seed, system and colour mode of the list), and print the rest. The colour mode is the list's mode.

WhereMeans
piece … print="missing"The default: print what the inventory lacks.
piece … print="always"Print the whole count whatever you have.
piece … print="skip"Leave it off.
plates inventory="ignore"Do not look in the inventory for this list: every count prints. "check" is the default. The editor's switch writes this word.
dharmatiles plates … --allThe same, for one run.

A list whose every piece is already on your shelf says so, with the way out, rather than lay out nothing. An inventory that has a mistake is never counted from: the list stops and shows the mistake (use --all to lay the list out without it).

In the editor

The inventory is listed in My tiles like a tile, and opens as a view. Four everyday things:

  • I have this. On a tile's level: 3 printed · seeds 7, 12, 97 for the target system, a Single colour or Multicolour switch (the last one you used is kept), and a button that adds one good print of the tile's current seed. It works without exporting anything, for the models you printed from an STL.
  • Have and need pills. A tile's row in a folder (My tiles or the library) carries have 2 or need for the target system. The strip under the crumbs says which system.
  • Plates. The plates' panel says N in inventory · M to print, with a switch, Only what I don't have or Everything, and lists each piece against the shelf.
  • After the print. After Export (and from any plate later, with Record a plate) a sheet lists the plate's pieces, all ticked good. Untick what failed, and one press adds the rest as good prints and the failures as failed, with today's date, each tile's hash and from="<list>/plate-N". The status line, the pills and the plates update at once, and the list is laid out again against the new shelf.

Open inventory.dinv for the whole view: the pieces grouped by tile, each with its seed, colour mode, how many you have, failures and losses, and edited since printing. Filters for system, colour and have (all, on the shelf, not on the shelf). For each piece:

  • Gone adds a gone line.
  • Reprint adds that exact piece, with its recorded seed and system, to a print list you choose, or makes a new one. A piece you still have is added with print="always"; one you do not is a plain piece, which prints because the inventory lacks it. A list laid out in another colour mode is warned about: the inventory counts the colour mode.

A tile that is no longer at its path (moved by hand, outside the editor) shows Not at this path any more with a one-click Re-link, which adds a renamed line. Source shows the file's own KDL, line numbered; edit it in any editor and the view follows.

The command

dharmatiles inventory                                  # what you have (DungeonBlocks); --system ol or all
dharmatiles inventory list --tile grass --colour multi --failed
dharmatiles inventory have lib:tiles/ground/1x1-grass --colour multi --count 2
dharmatiles inventory have home:meadows/glade --seed 12 --system ol --failed --note "stringing"
dharmatiles inventory gone lib:tiles/ground/1x1-grass --colour multi --note "dropped"
dharmatiles inventory relink home:meadow home:meadows/glade
dharmatiles plates my-list.dmap          # prints only what the inventory lacks
dharmatiles plates my-list.dmap --all    # every count

have takes the tile's own seed unless you give --seed, the date is today in UTC unless you give --on, and the colour mode is the last one you wrote unless you give --colour. gone refuses a piece you have none of. --json (before the action) gives the pieces as JSON.

Rules

  • The inventory is a log: lines are added, never edited away, and counts are worked out from it, never stored.
  • A piece is tile, seed, system and colour mode. DungeonBlocks and OpenLOCK never count for each other.
  • A failed print is kept and does not count. Two prints of one piece are two.
  • Edited since printing is information only: the piece still counts.
  • No file is made until the first line is written; a file that is not understood is never added to, and its mistakes are shown at their text.
  • Personal state stays out of print lists: the list says what to print, the inventory says what you own, the plates say how it lays out today.
  • Not tracked: where a piece sits in your storage, what colour of filament it is, which printer made it.
