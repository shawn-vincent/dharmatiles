The original library

How the Python engine actually builds a tile today, and what to keep, merge, or leave behind. The parts worth keeping are its ideas: paint-bucket regions, an ordered layer list, and "a floor is a wall laid flat". Much of the code has since been overtaken by the labs.

First, a warning about the docs. CLAUDE.md has drifted from the code:
  • cells_per_square defaults to 128, not 256.
  • relief_field, aged_relief and grass/growers/flat.py no longer exist. The surface finish is stone/finish.py:stone_relief.
  • Grass is now a wrapper over grass/thatch.py:ThatchGrass. It ignores the species and placement arguments that 30 tile specs pass (scatter/prototype.py:127).
  • Face colours are exported, as RGB15 STL and as 3MF.
Treat the code as ground truth.

How a tile gets built

A tile spec is a Python module that binds tile = Tile(surface, areas=[Region | Boundary …]). The orchestrator in terrains/tile.py walks the areas in order. Each layer's apply(scene, placement_mask) changes a shared TileScene and returns meshes. The red markers on the diagram show where the shared state has caused real bugs.

Working well and worth carrying over

keep

Paint-bucket regions

Region(selector=FloodFill(x, y)) over rasterised lines is already the conversation's region model. What's missing is named, reusable lines.

keep

Ordered layer list

List order as the contract is the seed of "the stack". The idea is sound. Its implementation through mutable shared grids is the problem.

keep

D[a:b].power(k)

A small distribution DSL used in every spec. It anticipates "any parameter may be a distribution".

keep

A floor is a wall laid flat

laid_flat=True on any wall family. The best example in the library of one parameter replacing a variant.

keep

Smooth-max block kernel

The masonry SDF kernel treats each cut as one more plane. It is the only true SDF in the library: a log-sum-exp of planes, marched with marching cubes (walls/masonry.py:440-486). It keeps its place as one way to build a unit.

keep

Crack network first

FieldstoneWall draws the crack tessellation first and morphs stones into its cells. Shawn called it "a thing of beauty". clifflab rediscovered the same idea.

keep

Opening solver

walls/fit.py is a deterministic fit solver with one Opening type, and the portcullis slot is one slice. It is clean.

keep

Organic leaf placer

Union-surface maximal Poisson placement plus batched embree rays. The only leaf generator Shawn kept.

keep

Guarantees by construction

Swept tubes are watertight without booleans. Wall blocks are exact. This is the method the labs then pushed further.

Accidental complexity

bug

Texture erases obstacles

displace_terrain ends with self.terrain_support_z[:] = self.terrain_z. Any texture layer that runs after a rock, wall or tree layer silently drops their support stamps. Thatch saves and restores the field to work around this.

bug

Every shore gets every strip

Ten tiles have two or more layered boundaries (water-corridor, -open and -turn with 2, -t with 3, -x with 4, each in +grass and +soil). Every boundary's SoilCarpet and Rocks runs over all the strips, and seeds carry no layer identity (layers/soil.py:68; scatter/prototype.py:108-116 never passes layer_idx). So the outputs are identical: on the -x tiles the soil is added 4 times and 4 identical stone sets stack on each other. Two SoilCarpets in disjoint regions are harmless; the bug needs overlapping masks.

smell

One grid, two meanings

terrain_support_z holds both solid geometry and the tree's soft "tall grass here" hint, so every reader has to guess which it is getting.

smell

233 hidden constants

Module-level _UPPER constants are the real tuning surface, and specs can't see them. Parameters live in three places: dataclasses, flat kwargs (Tree has 39, CutStoneWall 24 plus 14 class attributes), and module globals.

smell

Boundary does four jobs

It is a dividing line, a strip area, a host for layers, and a source of slope. In the new model these are a line, a derived band region, a definition applied to that region, and a field.

dead

Dead weight

FloppyGrass, grow_all, grass/mesh.build_meshes, FlatGrassGrower.step; six ignored Rocks fields; _rdp_edge, omit_top_mask, subsample; parked sheet-solidification constants. About 1,000 lines of CLI, batch, PDF and 3MF code live in terrains/tile.py next to the 500-line pipeline.

An OpenLOCK build is a second evaluation at 25.4 mm per square, not a parameter on one evaluation: footprints change, many draws depend on grid resolution (systems.py:99-109 caps OL at 64 cells per square), and the DungeonBlocks peg height is picked from the content's maximum Z (bases/dungeonblocks.py:20-37). With resolution-independent noise and path seeds, the two evaluations can share one layout.
