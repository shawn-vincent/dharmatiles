Unreleased

  • Report this defect: a message that means the program went wrong (a failure or bug of its own, a gate failure; never a mistake in your document) has a Report this defect button beside Copy. It shows the report that would be filed (the message’s copied text, the environment and your tile’s source, which a checkbox leaves out) and opens GitHub’s new-issue form filled in, with the labels defect and the code’s. A report too long for an address goes to the clipboard and the issue says to paste it. After a panic the command line prints report: <address>. The program makes the report once, from the message’s own text (GET /api/messages/report); see Errors.
  • dharmatiles fix mends tiles the language has outgrown: dharmatiles fix tile-or-folder collects every mistake that carries a fix (dt::seam, dt::near-edge, dt::edge-range, a misspelt word with a near one, an old control spelling, a number on a corner word) and shows the change with the millimetres a point moves on the target’s square; --write writes it, after which it checks again and repeats until no fix applies. A mistake with no fix is reported and the exit status is 1. A fix is data made once where the mistake is made (Fix in dt-doc, with moved for a moved point), the help is made from it, the editor’s button and the command line lay it in through the one applier (dt_doc::edit::apply_fixes). A corner word written with a number (nw(2)) and a one-square side word with a wrong number now carry their fix too.
  • A tile that does not build is the tile’s mistake, wherever a picture of it is wanted: a picture in the Add tiles grid, the seed strip, the plates, the map and the history of a tile with a mistake in its document (dt::seam, say) no longer logs “something went wrong inside” (kind=bug). The program’s tier event carries the mistake’s code, every picture’s caller gets it as one error (TileMistake), the picture shows the code where it would be, and the document that shows the piece gets the tile’s own messages (code, place, source line, help) instead of a bare “build failed”.
  • A copied message is enough to diagnose: every message carries the tile file (as the program names it), what was being done (the build or picture, with system, printer and seed) and the source line of its place; the one text that Copy all, the program’s own message route and a row’s Copy share now prints the file, the document it was seen from, the code with file:line:col, the source line with the span marked, the help, the kind (mistake, note, or the program’s own failure and who found it), and for a failure its causes and backtrace; a row’s Copy is that text plus the environment. GET /api/messages takes seq= for one message.
  • Live examples on the element pages: a <dt-example src="examples/…"> card shows a source and the tile it builds, and comes alive when touched: the engine (3.5 MB of WebAssembly, one worker shared by every card on the page, fetched only when wanted) builds the edited source at the browsing tier in a fraction of a second, and Full detail and Download STL build what a printer is given. A card has the controls its page picks (a slider or a seed roll that writes the number into the source), the messages as one strip folded to a status line (it opens by itself only for a new error; warnings are counted apart from notes, in the editor too), and an overlay: the caret or the pointer on a line, point, fill point or region of the source lights it on the tile, and the reverse, with toggles for lines, points, regions and squares. Each example is a .dtile under docs/examples/ that the page reads and a test builds (an expect-error card must give its code); the playground takes any source. The code is the editor’s own: the map JSON moved into dt_eval::map (one producer for the server and the browser), the messages store and list and a new status line component are shared, the overlay is split into geometry, marks with their states (off, shown, lit) and renderers, and the cards import the editor’s own files from one address, <site>/editor/js and /editor/vendor, which the deploy job and the program’s docs route each provide from web/preview (a page opened as a plain file does not run its cards; there is no second copy of the editor’s code in docs/). Posters are named by the build cache key (cargo xtask examples; the site’s posters job makes them), each with its map beside it so the overlay can be drawn before the engine wakes, and cargo xtask release writes the cards again with the new version before it commits. dharmatiles explain prints the local page’s real path, not one with .. in it.
  • Every error has an address: the program’s diagnostic codes (dt::type and the other 83) are one registry (dt-lang/src/codes.rs), and a test fails when a code is written as a string anywhere else. Each code has its own page, e/type.html: what happened, what to do, a broken document and its fix (a test proves the broken one gives the code and the fixed one reads clean), and a link on to the rule. A data-explains marker on the section of a docs page that explains a code owns that link; cargo xtask docs writes the #dt-… anchor and the error page from the two, and docs --check fails on a code with no section, a marker for no code, or a stale page or anchor. Every error a terminal prints ends with explain: <address> and dharmatiles explain dt::…, which prints the summary from the local copy of the page. The editor’s messages and error card have an Explain link that opens the copy served by the program from its own docs. The codes with no other home are explained on Error codes. The site’s address is derived from the repository address in Cargo.toml, in one place. .github/workflows/site.yml publishes the site to GitHub Pages on a release tag or a run by hand (module, posters and pages jobs, one deploy, a docs check on pull requests); the pages job publishes the committed docs/ after checking it.
  • Error pages use the width and show the message: each error page opens with the code, what happened and the message exactly as the program prints it (the program run on the page's broken document when cargo xtask docs writes it), then what to do beside the rule quoted from its section with a link to it in context, the broken document above its fix with the change marked, and a footer with the codes the same section explains, the list of every code and the offline explain line. The examples write the full header, dharmatiles version="1.0.0", as every library tile does. The change is marked by whole words, in plain ink on a red or green tint with a solid underline, and the examples keep their colours around it. Every code named on a docs page (the changelog aside) links to its error page, written by cargo xtask docs, and docs --check fails on a mention of a code that does not exist; on Error codes each definition is the section that explains its code.
  • Bambu printers as their own slicer has them: the X1 Carbon, P1S and P1P print to 250 mm and keep the cutter’s front-left corner (18 × 28 mm) clear, so a plate never puts a piece there; the H2C is 330 × 320 × 325 mm and the X2D 261 mm tall, each with two nozzles (2 filaments without an AMS). Their verify marks are gone.
  • The repair budget counts the worst of four seeds: the number of vertices the gate pushes apart (and the voids it fills) changes two or three times over with the seed, because the grass blades of a tile overlap in another arrangement, so a budget set from one seed tripped whenever a layout moved. Each tile’s count in the baseline is now the worst over the seed it writes and three fixed ones (EXTRA_SEEDS in the baseline test), and its max_* budget is held to that. The hash, triangles and overhang columns stay on the written seed. The first rewrite under this measure set the budgets afresh, so for most tiles they rose once; from there a rewrite only lowers them again. The full baseline builds each tile four times and takes about four times as long.
  • The editor’s title bar fits a phone: below 560 px wide the bar wraps into two rows (Tile/Map/Plates and Undo/Redo, then the target and the buttons) instead of running off the screen with the mode buttons stacked over the view.
  • “Control names are camelCase” has a fix button: a control written with its old spelling (per-square, bounded-by) is mended by one edit, made with the help in one place (DocError::advise_old, error::mend_camel). The count and perSquare advice stays text: how many is a choice, so no single edit mends it.
  • A region’s within line says the printed size from the program: the clause heading shows the distance as written (7dmm) and, only where it prints differently on the target, (prints 5.08 mm), from the same dt_doc::printed answer the sheet uses; the page no longer writes mm itself, shows 7dmm (7 mm) on DungeonBlocks or adds a unit to a bare number.
  • The page no longer guesses the square size: every place that fell back to 35 mm (the map overlay, the ground grid, the map plan, the scene grid, framing, the place tool) reads the size the program sends with the target (25.4 mm on OpenLOCK); where the program has not said it, nothing is drawn. A page test fails on any ?? 35, || 35 or 25.4 fallback.
  • Square at the seam: a line is one smooth curve through its points (cubic Bézier, handles 0.4 of the chord, Catmull-Rom directions inside), and an end exactly on a tile side leaves along the side’s normal, on a tile corner along its bisector, so two tiles that meet at a seam meet in the same direction (dt_kit::curve, run in DrawnLine::lay before the wobble, so walls, strips, regions, scatters and cliffs read one curve). curve=straight and ends=free on a line, and corner=#true, heading= and pull= on a through of one point, give the old or a hand-made look. The edge contract lists the seams, the places a line may cross a square’s edge (0, a third, a half, two thirds and 1, exact fractions: 1sq/3), the same on every square edge, closed under a quarter turn; a point on a side that is not one is dt::seam naming its column and row (counted from 1, column then row, C1 R1 the north-west square) and side, with a fix that snaps it to the nearest seam on that square, and seams=free on a tile opts out. A seam is named by a compass word from the table (nnw, n, nne along the north side, ssw s sse, wnw w wsw, ene e ese; nw ne se sw the tile’s corners), with the square in quotes on a longer side, "nnw(2)"; the dt::seam fix writes the word and an unknown word gets a did-you-mean fix. A point within 1 mm of a side but not on it is dt::near-edge, and a range on a side is dt::edge-range. Library tiles’ edge points moved onto seams (the 0.43/0.57 water channels are now a third wide, 1/3 to 2/3), so their shores, channels and walls change look; the tile-system page’s seam table is generated from the contract.
  • A tile that fails to read says so in the left panel, not “No tile”: the panel shows could not be read, the first mistake with its code and Go to line, from the same record the view’s card and the messages read (firstError), and the plates panel of a list that does not plan shows its mistakes where it showed only “does not plan”. “No tile” is decided in one place (tileLevelState) and a page test fails if a read error turns into it. Two flaky tests are deterministic: the folder-told-as-the-places test waits for the server to be idle and ends on a second folder instead of racing the start-up inventory, and the seed strip test waits for the five builds and cards it asked for instead of a fixed time.
  • Ink 5, second pictures: the map level opens with the map as a plan (its squares, each piece as a top-down picture in its place and turn, marked have, to print, other colour or left off, the selection outlined, press to select); the plates are small pictures of their beds at one scale, each piece a top-down picture where the packer put it; the inventory is a shelf of cards, one picture per print with its count; and each stack row has a thickness bar and its height span, which the program now measures in the mesh it builds (z on each entry of the mesh header's stack). The pictures are the page's one picture service, which gained a top-down view.
  • The editor pages show the editor: Preview, Maps, Plates and Inventory open with a screenshot of the editor, in light and dark, with numbered callouts and a key beside it, and Preview has one for each level it describes. cargo xtask shots redraws every picture from the running editor (a scratch home, a free port, headless Chrome) and records where each callout points, so the callouts follow a redrawn picture; cargo xtask docs --check fails when a page names a picture or callout that is not there.
  • The history menu shows what each step does: with the Undo or Redo menu open on a tile’s own text, each row has the tile as it is now and as the row would leave it. A wanted tier can be of a source text in place of the file’s (text and file on a want, POST /api/tiers/want), built on the tier lane (never behind an edit), kept by the text and cancelled when the page withdraws it (release on a begun picture now drops its want); a tier that fails says on the stream whether the cause is a mistake in the text (mistake) or the program’s own, so a history step with a mistake is a quiet row and anything else is loud.
  • The gate’s verdict is also a picture: beside the two bars the record shows the tile’s underside, seen from below, with the faces the gate painted in --over (past 65°) and --band (55 to 65°); it is drawn from the program’s own flags in the mesh the view holds (undersidePlan, from the one reading of them the worst-face button uses), not a second classification.
  • A map piece’s Seed level has the seed strip: the die beside its seed field lays the same five pictures the tile level’s seed row does (the piece’s seed first, a square on a seed you own); choosing one sets the piece’s seed. The strip, the die and the model that feeds them are one component (js/view/seed-strip.js, seedStripOf), used by both.
  • The parked weighting gallery is deleted: js/gallery.js, GET /api/weightings and its Rust (weightings.rs), their tests, the gallery’s styles and the slider they used are gone; the language’s weighted ranges (dt-value, dt_doc::lower) are unchanged.
  • Ink 4, messages act on their own advice: every “did you mean” carries a structured fix, the replacement for a span (Diag::fix, DocError::fix; fix on a message and on a check’s mistake in the contract), made in one place with the words of the help (dt_doc::error::suggest), and a test over the source fails for a suggestion written any other way. The messages panel, the view’s error card and the tooltip of the gutter mark show a button (Change to dirt) that applies it through the document’s one edit path, as one step of the history, only to the text it was found in.
  • The gate's repairs have a budget that cannot rise: the gate moves pinch vertices, fills sealed voids, removes slivers, collapses edges and drops loose bodies before it judges a mesh (about 74,000 pinch vertices and 3,666 voids across the library). tests/baseline/library-db.tsv now holds a budget for each of the five counts of each tile (max_voids, max_pinches, max_slivers, max_collapsed, max_dropped), and the baseline check fails when a tile repairs more than its budget, whatever else was rewritten. A rewrite can only lower a budget; to raise one, edit the file by hand where the diff shows it.
  • A print list and an inventory are edited by one set of operations: dt_doc::ops has one call, apply, and one list of operations (Op: add or bump a piece, append lines, set a count, remove, set a piece’s words, duplicate, pin, unpin) addressed by piece id, never by position, with the one EditError the .dtile edits already report. The twelve separate edit functions of dt_doc::map and inventory::append, which took ids or lines and answered with a string or a list of mistakes, are gone; every operation that names a piece writes ids on all of them first, in the same write. The editor's print-list and map calls make their edits through it. A file that does not read is refused with its own mistakes, as before.
  • A build is a product and a report: dt_eval::Built held 24 fields, the mesh and the gate's verdict beside the editor's data. It is now a Product (the export, materials, audit, record, output path, footprint and whether the gate checked it: everything a printer's file needs) and a Report beside it (stage hashes and timings, the surface and clouds the editor paints from, which entry made which triangle, what the caches did). A build reads as its product, built.report is the rest. The brick look is no longer a flag the evaluator works out from wall styles: dt_doc::schema::masonry_is_brick reads the words, a build carries dt_kit::Look. The cache stores the same bytes.
  • Printing is its own crate: dt-print holds the print list’s plan, the packer, the inventory on disk, binary STL, 3MF and Bambu Studio projects and the PNG renderer, moved out of dt-eval and dt-kit. dt-kit keeps the scene, the operations, the gate, the build record and the painter (the editor and the browser build show the same colours and neither prints). Builds are unchanged.
  • The disk cache is its own crate: dt-store holds the store (its SHA-256 keys, entries, eviction and codec) and the stored build calls build_stored and build_tier; dt-eval no longer knows a disk cache exists, only what a build reports of it (Built::cache). Builds and keys are unchanged.
  • The engine builds a tile in a browser: cargo xtask wasm <folder> now compiles the whole engine (dt-eval, dt-elements, dt-kit, dt-geom, and Manifold through wasm-cxx-shim) for wasm32-unknown-unknown, single-threaded, and writes a page that builds a tile in a Web Worker and shows it in three.js, painted as the editor paints it, with the gate’s verdict. Rayon is reached through one crate, dt-par (rayon everywhere but wasm32, where the same calls run in order), and a build’s stage clock through one function (dt_eval::clock); the engine’s code is unchanged. The page reads the library through the engine’s own Source trait, so the stage 1 copy of the file-loading loop is gone. Options::in_source reads the default printer through any Source. The vendored Manifold build for wasm applies the level-set patch the host build carries. Compiling Manifold for wasm needs brew install llvm lld cmake; cargo xtask wasm --check and the ignored test the_engine_compiles_for_the_browser check that the engine still compiles for the browser.
  • The language crates run in a browser, and a test keeps them able to: cargo xtask wasm <folder> builds dt-web (a new crate, left out of a plain cargo build) for wasm32-unknown-unknown and writes the bundle: the .wasm, its JS glue, the library as one JSON file and a page that checks a .dtile as you type, lists its stack with each length as written and as printed on both systems, and draws from a weighted range. It calls the same code the program does (dt_doc, dt_value); the range lowering (dt_doc::lower) and the use paths (dt_doc::paths) moved down from dt-eval to be shared. cargo xtask wasm --check, and the test dt-web/tests/wasm_core.rs, fail if dt-lang, dt-value, dt-doc or dt-web stop compiling for the browser.
  • Wilderness has mountains, not endless ridges: each of the two ranges has single peaks, rounded and organic in outline, rising out of its long run, with some stretches of the horizon left as saddles. Each range stays one flat blue-grey fading upward: no light and no depth inside it.
  • An editor page and a program from different builds refuse each other: the page imports a stamp of the contract (js/contract.js, written with api.d.ts) and the program compiles the same file in, and when the first snapshot's stamp differs the page shows only “This page and the program are different builds” and what to do, instead of the false errors a mismatched page showed.
  • Wilderness's grass meets its mountains without a pale line: the ground's distant haze is the colour of the mountains' foot, defined once for both.
  • Ink and Order, phase 4: say it, show it. A document that does not build leaves a card on the view in the plate’s own light colours with the first error in its words (Nothing built, the hint, Go to line, All messages), not an empty field. A message in the panel leads with its sentence (the word it is about in mono, never in backticks), then where it is and its code, quiet; pressing the row goes to its line, which replaces the Go to line button. The gate’s verdict is two bars (past 65°, the 55 to 65° band) full at the budget and red past it with the multiple written in the bar, the other numbers under Details. The inventory says On the shelf: 1 · printed today · single colour · seed 9486 with a picture of that seed, dates as a person says them (today, 13 Nov, 13 Nov 2025), the tile’s id in a tooltip and the log sentence only on the Inventory page. Printers are listed by the squares that fit (6 × 6 squares), each bed drawn at one scale, and the slicer imports are one menu.
  • A drystone wall never makes a stone that touches nothing: the fieldstone corner at seed 2 on OpenLOCK failed the gate (1 loose bodies dropped). Its top stone was a cell only 1.3 mm wide between two head joints, and the slant and bow each joint draws (up to 1.6 mm) leaned the two toward each other until the stone was a wedge 0.15 mm wide at its foot, floating clear of the course below. A head joint now moves from its cut by at most 0.3 of the narrowest stone beside it (the same number for both stones flanking it, so they still share one curve), which leaves every stone at least 0.4 of its width at every height. A unit test checks the reach for widths from 0.5 mm up and that both sides agree; a corner test tile (library/tests/walls/1x1-wall-fieldstone-corner) is built for OpenLOCK in the OpenLOCK test.
  • The sheet shows every control’s real default where it is not written, not “not set”: a wall entry showed stones, joints, edges and ruin as not set and a select offered a disabled not set, though the element picks a value in its own code. Now every control shows the value a build uses, faint, with where it comes from beside it (default, from style brick, from crown branching normal, from parts/edges, or the part an entry’s value is written in); where leaving a control out has no number, the words say what it means (a plain line, no strip, a mix of all three). There is one source for each: what an element works out for itself is read off the fields it is built with (Element::shown: a wall’s stone size, joints and bond from its style, a scatter’s perSquare, gap and reach by what it scatters, a tree’s branch numbers from branching, a cliff’s stone weights from rock), else the schema’s default, else its new absent words; a body’s top is the band the solver used, with the library file it is the default of. The program sends it with each entry (defaults in the stack items; dt_eval::unwritten) and the page only shows it; a control with none of the three is an error, and a test runs every element through it. A group’s controls are rows of their own, named by their path (stones height), and writing one of them writes the group’s line (stones height=…). A wall’s sheet no longer lists a second height.height row: the number a written word stands for was listed as if the document had written it. Builds are unchanged.
  • Library walls and floors follow the tile seed, and the seed row says what does not: every library wall (brick, fieldstone and cut stone, straight and corner, and the curve), the stone and plank floors and the floor with a wall pinned their entries with a seed= of their own, so rolling the tile seed (the dice, its five pictures, --seed) never changed the wall or the slabs: brick walls seem to be identical regardless of the seed chosen. The pins are taken out of the library tiles. On the tile level’s seed row a quiet line names the entries that keep a seed of their own (wall keeps its own seed (15), wall and flagstones keep their own seeds), read from the stack the program describes, and pressing a name selects that entry. The map piece’s Seed level does not show it yet.
  • The sheet shows lengths as written and as printed: a length reads as you wrote it with its unit (7 dmm, a range 3.5–6.5 dmm, a count of nothing none, a map piece’s place column 1, row 1), the unit’s tooltip is the program’s own sentence (unitAbout in /api/language, from dt_lang::unit_about), and beside it, quieter, is what it prints on the build target (7 dmm · prints 5.08 mm on OpenLOCK), worked out by the program (dt_doc::printed, POST /api/tiles/ID/printed) with the same reader and evaluator as a build, shown only where it differs from the written number. Typing is literal and never converts a unit; a printed number is typed too and written back in the value’s own unit (5 against 7dmm on OpenLOCK is 6.89dmm, POST /api/printed-set), to 0.01 mm with the fewest decimals. The page’s second copies of the square are gone (a dropped tile snapped to system === 'ol' ? 25.4 : 35, a line’s wobble was scaled by sq / 35); a test fails if the page multiplies or divides by 35, 25.4 or a dmm scale. The schema’s length axis is Axis::Dmm and reads dmm on the wire (it said mm), and the unit-free reader’s message says sizes are dmm.
  • The folders of Add are steps of the one trail, not a second navigation: the Add pane drew its own crumb bar, its own ‹ and its own slide over the folders it browsed, inside the panel. Now each folder is a level of the one shell: Places › My tiles › first-plate.dmap › Add › Places › My tiles › dungeon, every crumb pressable, opened by pressing a folder, left by ‹, Esc, ⌘[ or a crumb, moving with the one slide (deeper from the right), the keyboard and arrow keys handled by the shell. Add tiles opens at the folder you last browsed in Add this session, else the folder the map is in. The address names the folder (add=<place>&adir=<folder>, in place of add=1) and each folder is a step of the browser’s history, so a reload and Back and Forward land on it. The pane’s bar, button, slide and folder-walking state are deleted (levelDepth in nav.js is the one depth of a level, the Add step’s folders included); a test fails if the pane draws a crumb bar, an up button or a sliding list of its own.
  • Ink and Order, phase 2: one system for the editor. Four type sizes (12, 14, 17 and the display 24, as --fs-s to --fs-xl with their line heights; 12 px is the floor, where the editor had thirteen sizes down to 10) and a test that fails on a raw size. No caps labels: one .cap (sentence case, 12 px, 600, the ink) replaces the twelve uppercase rules, with a test. Plex for sentences and words, mono only for what you would type (a word value, a stack row’s sub-line and a plate’s families were mono). Two control heights (--h-sm 24, --h-md 30; a segmented control is 30 around 24), one corner set (--r, --r-lg, and 2 px for marks: no pill is left, the target chip and every count are square-cornered) and one 8 px square status mark for a tile, a build, a message, a stack row and the status line; tests fail on a stray height, a stray radius and a second mark. One header band per level: the name large in Big Shoulders over one quiet line (what it is, where it stands in the stack, Help), with the Outline | Source switch at its right, replaces the three bands that said the same name; the sheet has one left edge for labels, one for values and one right edge for × and ›. One icon set: the arrows, check, cross, ellipsis, turn arrows, sun and moon, panel toggles, copy, undo and redo are Lucide (one licence note) with the folder glyphs and the dice, drawn by one helper (js/view/icons.js), and a test fails on a character standing in for an icon. The panel switch reads Outline | Source in every document and the title bar’s mode switch lights no mode in a folder or the inventory. The display menu is a grid (label, switch and key on one baseline; the backdrops two by two with a swatch; all nine cameras with their icons), and is never taller than the part of the view you can see, scrolling inside itself, from the same box the canvas resizes to (also while the messages panel is dragged or animating).
  • The view bar is four pinned cameras that show where the camera is: Iso, Top, Front and Close-up in fixed places, drawn as cubes after the standard views of CAD programs (a see-through cube with the face you look at filled for the six sides; the cube solid for Iso, Low and Close-up; all nine differ), the word as the tooltip. The pressed one follows the camera: lit within 2 degrees of a preset, on opening (Iso was never lit until you pressed one: the bar read the derived state before it existed), after Top, and after an orbit that comes back to a preset or leaves it. The display menu shows all nine with the same icons. Under now fades the backdrop out so the tile is seen from below instead of hidden behind earth.
  • The panel toggles move to the right of the title bar and both panels animate: the left panel’s button was left of the logo, reserving a place for a rare action; the logo starts the bar now, and the left-panel and messages buttons sit beside the theme button, each pressed while its panel is open (\ and ⌃J in the tooltips; the status line opens the messages too, the same state).   • Under the hood, the editor and the program: a tile is named by an id (not its place in the list), so a tile that is deleted leaves no empty slot and a page that reconnects finds its tile again by name; a draft is one request answered with its mesh, with no event, second route or waiting handshake; one build queue holds drafts, tiles asked for and tiles that changed, and a newer draft of a tile cancels the older; the event stream numbers its changes and resumes after a drop instead of starting over; and request reading is separate from routing, so routes are tested without a socket. In the page, three small stores (the server's word, the view, the text) replace one shared bag of state, each part draws by subscribing to them, and the selection is one shape.
